# Развёртывание 3x-ui + REALITY на общем порту 443

Это руководство посвящено использованию 3x-ui для управления узлом, чтобы панель, подписка, веб-сайт и REALITY работали через публичный порт `443`. Основная идея заключается в том, что публичная сеть `443` предоставляет только одну услугу, соответствующую текущему режиму входа: `nginx-stream` использует Nginx stream для разгрузки в соответствии с SNI, `tcp-peek` использует `vpso-mux` для разгрузки в соответствии с SNI, а `xray-fallback` использует Xray главный входящий захват 443 и резервный вариант для локального механизма обратный прокси Интернета; все локальные серверы пытаются отслеживать `127.0.0.1`.

Рекомендуется сначала прочитать полное руководство по 443:

```text
docs/443-single-entry.md
```

При устранении неполадок обратите внимание на:

```text
docs/443-single-entry-troubleshooting.md
```

## Пример описания

Имена доменов, пути и порты в этой статье приведены в качестве примеров и не являются фиксированными значениями, которые необходимо копировать. `panel.example.com` — пример доменного имени панели, `node.example.com` — пример доменного имени узла, `site.example.com` — пример доменного имени веб-сайта, `40000` — пример порта панели 3x-ui, `2096` — пример порта подписки, а `8443` — пример локального веб-порта механизма обратный прокси, `1443` — это пример локального порта Xray/REALITY.

Пожалуйста, замените его собственным доменным именем, путем и портом во время фактического развертывания; если сценарий уже сохранил конфигурацию, текущее отображение сценария будет иметь преимущественную силу. Не копируйте слепо примеры из руководства.

| 3x-ui | Порт панели, путь, путь к сертификату, настройки подписки, входящий REALITY | Если путь к панели или сертификат установлены неправильно, она не откроется. |

## Рекомендуемая архитектура

```text
Публичная сеть 443 -> Единая услуга, соответствующая текущему режиму входа
  nginx-stream  -> Nginx stream маршрутизация по SNI
  tcp-peek      -> vpso-mux маршрутизация по SNI
  xray-fallback -> Xray основное входящее подключение принимает порт 443 И fallback местному Web механизм обратного прокси

panel.example.com  -> текущий Web механизм обратного прокси (Caddy или Nginx, Например 127.0.0.1:8443)-> 3x-ui панель 127.0.0.1:40000
panel.example.com/sub/ -> текущий Web механизм обратного прокси (Caddy или Nginx)-> 3x-ui Подписаться 127.0.0.1:2096
REALITY SNI / неизвестно SNI -> Xray REALITY 127.0.0.1:1443
site.example.com -> Caddy/Nginx местный Web обратный прокси -> бэкенд локального веб-сайта
```

Ключевые принципы:

| принципы | Описание |
|---|---|
| публичный порт `443` предоставляет только одну услугу, соответствующую текущему режиму входа. | Не позволяйте Caddy, Xray, панели и `vpso-mux` захватывать порты друг у друга. |
| Механизм веб-обратный прокси прослушивает локальный порт HTTPS. | Браузер HTTPS обрабатывается локальным обратным веб-прокси Caddy или Nginx, `8443` — это всего лишь пример значения. |
| Панель 3x-ui не использует собственный сертификат в качестве публичной сети HTTPS. | Панель как локальный сервер HTTP |
| REALITY использует внешний реальный SNI | Не записывайте `dest` в качестве собственного доменного имени панели. |
| Укрепите брандмауэр после успеха | Сначала пройдите, затем оставьте только необходимые порты |

`Xray управление входящими подключениями` записывает только `SNI -> локальный адрес:порт`, а не входящий редактор 3x-ui; вам необходимо сначала создать и включить локальное входящее подключение в 3x-ui. Режимы Nginx Stream и TCP Peek + Splice поддерживают множественный локальное входящее подключение Xray по SNI; Сам Xray может иметь несколько входящих подключений, но в резервном режиме xray публичный порт `443` по умолчанию использует один Xray. Основной входящий захват, сценарий в настоящее время не поддерживает непрерывное распространение нескольких SNI на несколько локальных входящих Xray в этом режиме.

Обычные TLS и REALITY следует оценивать отдельно: Обычный TLS уделяет больше внимания тому, совпадают ли локальный сертификат, веб-резервный вариант и Host/SNI; REALITY уделяет больше внимания тому, действительно ли внешний целевой сайт доступен и стабильны ли характеристики TLS. REALITY не требуется. `serverName` присоединяется к механизму обратного веб-прокси и не требует локального сертификата для покрытия REALITY `serverName`. Политика сертификатов по-прежнему использует `acme.sh + Cloudflare DNS API`, не использует модуль Caddy DNS и не требует `xcaddy`. 3x-ui Сертификат, выбранный на этапе установки, используется только для завершения процесса установки и не является схемой сертификата, которая в конечном итоге используется общей точкой входа 443.

## Этапы работы

### 1. Проведите предварительную проверку

Введите:

```text
Главное меню [1 Предварительная проверка и анализ рисков]
```

Ключевые моменты для подтверждения:

| Проект | Ожидание |
|---|---|
| DNS | Может разрешить ваше домен и внешний сайт HTTPS. |
| порт | Текущий статус занятости `443` ясен. |
| система | Доступно для систем Debian/Ubuntu/RHEL. |
| время | Системное время точное, выдача сертификата зависит от времени |
| Менеджер пакетов | Не занят другими процессами |

Проверьте публичный порт `443`:

```bash
ss -lntp | grep ':443' || echo "443 не прослушивается"
```

Если Caddy/Nginx/Apache уже занимает публичный порт `443`, сначала запишите существующее домен сайта и внутренний порт, а затем перерегистрируйте его через `Главное меню [19 443 центр управления общим входом] -> [8 менеджмент Web домены / обратный прокси]`.

### 2. Установите или введите 3x-ui.

Введите:

```text
Главное меню [5 панель、Узлы и инструменты подписки] -> [1 3x-ui скрипт панели]
```

Если 3x-ui ещё не установлен, установите его. В текущем официальном установщике выберите пункт 4: `Skip SSL (advanced — behind reverse proxy / SSH tunnel only)`. Для общей точки входа 443 это рекомендуемый вариант; когда установщик спросит о привязке только к `127.0.0.1`, введите `y`.

Риск: выбирайте Skip SSL только при уже настроенном обратном прокси или SSH-туннеле. Во время установки сразу привяжите панель к loopback и не открывайте незашифрованный HTTP-порт панели в Интернет.

| Опции установщика | Роль в этом уроке | Последующая обработка |
|---|---|---|
| Skip SSL | Рекомендуемый локальный HTTP-бэкенд | Привязать только к `127.0.0.1` |
| Подать заявку на сертификат на домен | Может использоваться для временного завершения установки 3x-ui. | Очистите путь сертификата 3x-ui перед доступом к 443. |
| Запросить сертификат на IP | Только как временный переход, не рекомендуется как формальный Интернет HTTPS | Очистите путь сертификата 3x-ui перед доступом к 443. |
| Выберите существующий путь сертификата | Может использоваться для временного завершения установки. | Очистите путь сертификата 3x-ui перед доступом к 443. |

Окончательная архитектура такова: Интернет HTTPS единообразно обрабатывается текущим механизмом обратного веб-прокси (Caddy или Nginx), а сертификаты применяются и устанавливаются VPS-Optimize с использованием `acme.sh + Cloudflare DNS API`; Панели и подписки 3x-ui используются только в качестве локального бэкэнда HTTP, собственный сертификат 3x-ui не используется в качестве окончательного решения для интернет-сертификатов.

При выборе Skip SSL настройте локальную привязку сразу; не используйте публичный порт панели как временное решение.

Рекомендуется записывать следующие значения:

| Проект | Пример |
|---|---|
| Порт панели | `40000` |
| Путь панели | `/panel/` |
| учетная запись администратора | Сохрани это сам |
| Пароль администратора | Сохрани это сам |
| Порт подписки | `2096` |
| Общий путь подписки | `/sub/` |
| Clash/Mihomo путь | `/clash/` |

### 3. Очистите путь сертификата панели 3x-ui.

Если вы готовы получить доступ к общему входу 443 в VPS-Optimize, вам следует очистить панель 3x-ui и путь к сертификату подписки, чтобы позволить механизму обратного веб-прокси взять на себя управление Интернетом HTTPS.

Войдите в панель 3x-ui:

```text
Поля `webCertFile` и `webKeyFile` в настройках панели
```

Очистите все похожие поля:

```text
Путь к сертификату
Путь к закрытому ключу
Путь к файлу открытого ключа
Путь к файлу закрытого ключа
```

Сохраните и перезапустите панель.

Причина: после доступа к общему входу 443 интернет-HTTPS обрабатывается механизмом обратного веб-прокси, а панель 3x-ui служит только локальным бэкэндом HTTP. Если этот параметр не отключен, это может привести к ошибке 502 Bad Gateway, несоответствию внутреннего протокола HTTP/HTTPS, петле перенаправления, путанице пути сертификата, исключению панели или подписки.

### 4. Настройте привязку панели

Набор примерных значений:

| Проект | Пример значения |
|---|---|
| `webListen` | `127.0.0.1` |
| `webPort` | `40000` |
| `webBasePath` | `/panel/` |
| `webCertFile` / `webKeyFile` | Очистить |

Прежде чем получить доступ к общей точке входа 443, следует изменить его на `127.0.0.1`, привязать его локально и закрыть панель HTTPS; Доступ в Интернет использует только общая точка входа 443 и механизм обратного веб-прокси и не резервирует публичный порт панели в качестве перехода.

Проверьте локальный бэкэнд:

```bash
curl -I http://127.0.0.1:40000/panel/
```

### 5. Настройте подписку.

Пример в настройках подписки 3x-ui:

| Проект | Пример значения |
|---|---|
| `subListen` | `127.0.0.1` |
| `subPort` | `2096` |
| `subPath` | `/sub/` |
| `subClashPath` | `/clash/` |
| `subCertFile` / `subKeyFile` | Очистить |
| `subDomain` | `panel.example.com` |

В `subDomain` указывается только домен, без `https://`, порта и пути. В `subPath` и `subClashPath` сохраняйте `/` с обеих сторон. Не указывайте:

```text
sub
/sub
sub/
/sub/КлиентSubscription
```

Подтвердите локальную подписку:

```bash
curl -I http://127.0.0.1:2096/sub/
```

Если 404, сначала проверьте, включена ли служба подписки 3x-ui и согласованы ли пути.

### 6. Создайте новый входящий REALITY.

Добавьте входящий VLESS REALITY в 3x-ui, пример:

| Проект | Пример значения |
|---|---|
| соглашение | VLESS |
| передача | TCP / RAW |
| Security | REALITY |
| адрес прослушивания | `127.0.0.1` |
| порт прослушивания | `1443` |
| uTLS | chrome |
| `dest` / `Target` | `www.microsoft.com:443` или другой внешний реальный сайт HTTPS |
| `serverNames` / `SNI` | `www.microsoft.com` |
| SpiderX | `/` |
| Fallbacks | Оставьте пустым |

Не пишите:

```text
panel.example.com:443
node.example.com:443
127.0.0.1:8443
```

Сначала убедитесь, что замаскированный SNI можно подключить:

```bash
openssl s_client -connect www.microsoft.com:443 -servername www.microsoft.com </dev/null
```

Вы можете увидеть выходные данные сертификата, указывающие, что внешний сайт SNI доступен.

В новых версиях 3x-ui пустой `Min Client Ver` не означает отсутствие ограничений: используется встроенная минимальная версия Xray core. Если сторонний клиент не подключается, сначала обновите его core. Значение `1.0.0` рассматривайте только при подтверждённой необходимости совместимости и принятом риске устаревших отпечатков.

### 7. Первая настройка общего входа 443.

Введите:

```text
Главное меню [19 443 центр управления общим входом] -> [2 Первая настройка/установка 443 единственный вход]
```

Пример заполнения:

| Проект | Пример значения |
|---|---|
| домен панели | `panel.example.com` |
| Маскировка REALITY SNI | `www.microsoft.com` |
| 443 Режим входа | `nginx-stream` / `xray-fallback` / `tcp-peek` |
| Папка Интернет `443` | Захвачен одной служба входа, соответствующей текущему режиму точки входа. |
| Локальный адрес прослушивания механизма веб-обратный прокси | `127.0.0.1` |
| Локальный порт прослушивания механизма веб-обратный прокси | `8443` |
| Xray REALITY локальный адрес прослушивания | `127.0.0.1` |
| Xray REALITY локальный порт прослушивания | `1443` |
| Адрес привязки панели 3x-ui | `127.0.0.1` |
| Порт панели 3x-ui | `40000` |
| Интернет-путь панели 3x-ui | `/panel/` |
| Адрес прослушивания подписки 3x-ui | `127.0.0.1` |
| Порт подписки 3x-ui | `2096` |
| Префикс общего пути подписки | `/sub/` |
| Префикс пути Clash/Mihomo | `/clash/` |

Если `/etc/vps-optimize/sni-stack.env` не имеет `ENTRY_MODE`, скрипт будет обрабатываться как `nginx-stream` только тогда, когда он совместим с чтением старой конфигурации; новые конфигурации и последующие сохранения должны основываться на фактическом выбранном `ENTRY_MODE`.

Когда в скрипте появится карточка подтверждения высокого риска, перед вводом заглавных букв `YES` подтвердите выполнение следующих условий:

- Снимок VPS создан.
- Текущая сессия SSH не отключена.
- Группа облачной безопасности выпустила порты SSH и `443/tcp`.
- домен панели DNS было разрешено текущему VPS.
- Токен Cloudflare имеет правильные разрешения.

### 8. Запустите проверка состояния соединения.

Введите:

```text
Главное меню [19 443 центр управления общим входом] -> [13 443 Проверка соединения]
```

При проверке работоспособности проверяется текущая служба входа, механизм обратного веб-прокси, REALITY, бэкенд панели, остаток пути к сертификату панели/подписки 3x-ui и элементы безопасности.

Дополнительные проверки вручную:

```bash
ss -lntp | grep -E ':443|:8443|:1443|:40000|:2096'
curl -I https://panel.example.com/panel/
curl -I https://panel.example.com/sub/
openssl s_client -connect серверIP:443 -servername panel.example.com </dev/null
```

Ожидания:

| Проверить элементы | Ожидание |
|---|---|
| публичный порт `443` | Связано только с одной службой записи, соответствующей текущему `ENTRY_MODE`. |
| Механизм веб-обратный прокси | `127.0.0.1:8443`, при условии текущей конфигурации скрипта |
| REALITY | `127.0.0.1:1443` |
| панель | `127.0.0.1:40000` |
| Подписаться | `127.0.0.1:2096` |
| Доступ через браузер | `https://panel.example.com/panel/` |

### 9. Проверьте подписку клиента, Хосты/Внешние прокси и REALITY.

Ссылки на подписку не должны появляться:

```text
:2096
:40000
:8443
127.0.0.1
```

Ссылка на узел должна выводить публичный порт `443`.

3x-ui v3.4.0 и новее: откройте `Hosts / Хост` и добавьте хост:

```text
Входящее подключение: выберите это подключение REALITY
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
Security: то же значение или фактический тип защиты этого входящего подключения
SNI / Fingerprint / ALPN：Поддерживайте фактическое значение входящего и клиентского трафика согласованным
```

3x-ui v3.3.1 и более ранние версии: откройте `External Proxy` во входящем REALITY:

```text
Тип: то же значение
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
```

Ключевые моменты для подтверждения в узле REALITY:

| Проект | Ожидание |
|---|---|
| адрес | домен узла или IP-адрес сервера в Интернете |
| порт | `443` |
| security | `reality` |
| SNI | Внешний реальный сайт HTTPS |
| flow | В соответствии с вашим клиентом и входящими конфигурациями |

Если панель открывается нормально, но REALITY не может подключиться, сначала проверьте, работают ли `dest`, `serverNames`, локальный порт прослушивания и маршрутизация SNI или резервное переключение Xray в текущем режиме входа, как ожидалось.

## Метод проверки

Полная команда проверки:

```bash
ss -lntp
systemctl status nginx --no-pager
systemctl status caddy --no-pager
curl -I https://panel.example.com/panel/
curl -I https://panel.example.com/sub/
curl -I http://127.0.0.1:40000/panel/
curl -I http://127.0.0.1:2096/sub/
openssl s_client -connect серверIP:443 -servername panel.example.com </dev/null
```

```text
Главное меню [19 443 центр управления общим входом] -> [13 443 Проверка соединения]

```

## Как откатиться, если не удалось

| ситуация | Процесс |
|---|---|
| Nginx/Caddy не удалось выполнить после записи конфигурации. | Скрипт сделает все возможное, чтобы автоматически вернуться к этой резервной копии. |
| Панель невозможно открыть | `Главное меню [5 панель、Узлы и инструменты подписки] -> [3 панель SSL Ремонт]` Очистите панель SSL, затем проверьте локальный порт |
| Сертификат не удался | `Главное меню [19 443 центр управления общим входом] -> [12 CF DNS / Caddy Обслуживание сертификатов]` Проверьте токен, DNS и повторно подпишите сертификат. |
| 443 занято | `ss -lntp | grep ':443''`, чтобы найти оккупанта, а затем настроить его на локальную привязку |
| Подписаться 404 | Проверьте, соответствует ли путь подписки 3x-ui текущему пути механизма веб-обратный прокси. |
| REALITY не удалось | Проверьте локальное прослушивание REALITY, SNI, порты конечного и клиентского узла. |
| Общая конфигурация сбивает с толку | `Главное меню [16 Резервное копирование и откат конфигурации] -> [3 Восстановить из резервной копии]` Откат из резервной копии вручную |

## Распространенные ошибки

| Ошибка | явление | Процесс |
|---|---|---|
| Механизм веб-обратный прокси также контролирует публичный порт `443`. | Текущую служба входа не удалось запустить или произошел конфликт портов. | Механизм обратного веб-прокси заменяется на локальную привязку, например `127.0.0.1:8443`. |
| 3x-ui поставляется с панелью HTTPS Не имеет значения | Цикл перенаправления, ошибка сертификата | Очистите путь к сертификату панели и перезапустите. |
| REALITY Напишите собственное домен, чтобы создать SNI. | Не удалось подключиться к клиенту | Переход на внешний реальный сайт HTTPS |
| Путь подписки не содержит `/`. | Подписаться 404 | Пишите равномерно `/sub/`, `/clash/`. |
| REALITY/домен узла включено Cloudflare Orange Cloud | Клиент не может подключиться напрямую к VPS | домен узла изменено на DNS only/Grey Cloud; проблема с сертификатом DNS-01 проверяется индивидуально на предмет распространения токена, зоны и TXT. |
| В `subDomain` указаны схема, порт или путь | Подписка возвращает 404 или Host не совпадает | Укажите только `panel.example.com` |
| Хосты/Внешний прокси-сервер, выходной внутренний порт | Клиентский узел не может подключиться к публичный порт `443`. | 3x-ui v3.4.0+ проверьте `Hosts / Хост`; проверка старой версии `External Proxy` |
| Повторный запуск без резервной копии | Конфигурация становится запутанной | Сначала сделайте резервную копию, а затем следуйте инструкциям по устранению неполадок, чтобы исправить ее по пунктам. |
