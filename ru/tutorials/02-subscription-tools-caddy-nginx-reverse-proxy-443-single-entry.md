# Обратный прокси для отдельного сервиса подписок через Caddy/Nginx и порт 443

Это руководство поможет безопасно открыть HTTPS-доступ к SublinkPro, Sub-Store и Miaomiaowu Subscription Management. До включения повторного использования порта 443 используйте Caddy или Nginx HTTPS из `Главное меню [4 Обратный прокси]`. После включения добавляйте домен через меню Web-доменов и обратного прокси повторного использования порта 443; там же выбирается локальный Web-движок Caddy или Nginx.

## Выбор схемы

| Текущий статус | Рекомендуемый метод |
|---|---|
| Повторное использование порта 443 ещё не включён; нужен только доступ к сервису по домену | Откройте `Главное меню [4 Обратный прокси]` и выберите Caddy или Nginx HTTPS для текущей среды. |
| Повторное использование порта 443 включён | Добавьте домен в `Главное меню [19 Повторное использование порта 443] -> [8 Управление Web-доменами и обратным прокси]`. При необходимости переключайте Caddy/Nginx через его пункт `[8 Сменить Web-движок обратного прокси]`. |
| Сервис используется только вами | Привяжите бэкенд к localhost или частной сети, а внешний доступ дайте через Caddy, Nginx или повторное использование порта 443. |
| Непонятно, какую схему выбрать | Выполните `Главное меню [1 Предварительная проверка и анализ рисков]` и `Главное меню [15 Обзор состояния служб]`, чтобы проверить порты и службы. |

## Когда подходит это руководство

| Ситуация | Подходит? |
|---|---|
| Развёртывание SublinkPro | Да |
| Развёртывание Sub-Store | Да |
| Развёртывание Miaomiaowu Subscription Management | Да |
| Добавление HTTPS к сервису подписки, уже работающему в Docker | Да |
| Прямое открытие внутреннего порта сервиса в Интернет | Нет |

## Что подготовить

| Материал | Пример | Описание |
|---|---|---|
| Снимок VPS | Создайте в панели облачного провайдера | Рекомендуется перед изменением обратного прокси или контейнера. |
| Домен подписки | `sub.example.com` | DNS-запись указывает на этот VPS. |
| Адрес и порт бэкенда | `127.0.0.1:3000`, `10.0.0.20:3000` | Примеры локального и частного бэкенда; замените фактическими значениями. |
| Cloudflare API Token | `Zone.Zone.Read`, `Zone.DNS.Edit` | Нужен для выдачи сертификата через DNS-проверку. |
| Текущий сеанс SSH | Не закрывайте | Нужен для восстановления при ошибке. |
| Docker/Compose | Скрипт проверит и установит при отсутствии | Сервисы подписок обычно развёртываются через Docker Compose. |

Рекомендации по DNS:

| Домен | Рекомендация |
|---|---|
| `sub.example.com` | DNS only / прокси Cloudflare выключен |
| Домены повторного использования порта 443 | DNS only / прокси Cloudflare выключен |
| Обычный Web-сайт | Включайте прокси по необходимости, но сначала завершите настройку с выключенным прокси. |

## Что будет изменено?

| Компонент | Возможные изменения | Риск |
|---|---|---|
| Docker/Compose | Добавляйте новые контейнеры, сети и каталоги развертывания. | Конфликт порта контейнера или сбой получения образа |
| Caddy | Конфигурация сайта, сертификаты и правила обратного прокси | Ошибка конфигурации может привести к 404 или 502. |
| Обратный прокси Nginx HTTPS | HTTPS-конфигурация сайта, когда повторное использование порта 443 выключен | Ошибка или конфликт портов может нарушить доступ к 80/443. |
| Nginx Stream | Маршрутизация по SNI при повторном использовании порта 443 | Ошибка может повлиять на публичный порт `443`. |
| Межсетевой экран | Открыты должны быть только входные, а не внутренние порты | Неверное правило может открыть внутренние сервисы. |
| Резервные копии | Конфигурационные копии и каталоги изоляции | Занимают немного места на диске. |

## Шаги

### 1. Сначала проверьте сервер

Введите:

```text
Главное меню [1 Предварительная проверка и анализ рисков]
```

Проверьте следующее:

| Пункт | Ожидаемое состояние |
|---|---|
| Docker | Если Docker отсутствует, установщик сервиса установит его. |
| Использование порта | Порт сервиса не конфликтует с существующей службой. |
| DNS | Домен подписки разрешается на этот VPS. |
| Межсетевой экран | Разрешены SSH и входной порт. |
| Системное время | Для выдачи сертификата требуется точное время. |

Проверьте порт вручную:

```bash
ss -lntp
```

### 2. Установите сервис подписки

Введите:

```text
Главное меню [5 панель、Узлы и инструменты подписки]
```

В процессе установки автоматически проверяются Docker/Compose и устанавливаются первыми, если они отсутствуют.

Распространённые пути меню:

| Сервис | Путь меню | Сценарий |
|---|---|---|
| SublinkPro | `Главное меню [5 Панели, узлы и сервисы подписок] -> [7 Стек подписки SublinkPro]` | Преобразование, агрегация и управление подписками. |
| Miaomiaowu Subscription Management | `Главное меню [5 Панели, узлы и сервисы подписок] -> [8 Стек подписки Miaomiaowu]` | Графическое управление подписками. |
| Sub-Store | `Главное меню [5 Панели, узлы и сервисы подписок] -> [9 Стек подписки Sub-Store]` | Расширенная обработка подписок и сценарии. |
| Dockge | `Главное меню [5 Панели, узлы и сервисы подписок] -> [11 Dockge Compose]` | Управление несколькими проектами Compose. |

После установки сначала проверьте статус контейнера:

```bash
docker ps
```

Если скрипт размещает проект в `/opt`, выведите содержимое каталога:

```bash
ls /opt
```

### 3. Проверьте привязку бэкенда

Привяжите бэкенд сервиса к localhost или частной сети, а не открывайте его напрямую в Интернет. Ниже приведены примеры:

```text
127.0.0.1:3000
10.0.0.20:3000
```

Проверьте:

Запустите команду для фактически используемого адреса бэкенда.

```bash
ss -lntp | grep -E ':3000|:3001|:3002'
curl -I http://127.0.0.1:3000/
curl -I http://10.0.0.20:3000/
```

Если бэкенд слушает `0.0.0.0:3000`, он может быть доступен из Интернета. Ограничьте доступ локальной защитой Docker или правилами межсетевого экрана:

```text
Главное меню [11 Docker Управление безопасностью]
Главное меню [8 Правила брандмауэра]
```

Локальная защита Docker меняет его сетевое поведение и перезапускает Docker. Перед её применением убедитесь, что контейнеры не зависят от напрямую открытых публичных портов.

### 4A. Вариант 1: Caddy/Nginx без повторного использования порта 443

Выберите этот вариант, если повторное использование порта 443 ещё не включён и нужен доступ к сервису по домену.

Введите:

```text
Главное меню [4 обратный прокси]
```

Выберите в соответствии с текущей средой:

| Вариант | Когда использовать |
|---|---|
| `[1 Добавить обратный прокси Caddy]` | Вы уже используете Caddy или хотите поручить ему управление сайтом. |
| `[2 Добавить обратный прокси Nginx HTTPS]` | Повторное использование порта 443 выключен, а Nginx должен слушать публичные 80/443 для HTTPS. |

Используйте эти значения только как пример; замените домен и порт своими значениями:

| Пункт | Пример |
|---|---|
| Домен | `sub.example.com` |
| Порт бэкенда | `3000` |
| Протокол бэкенда | Зависит от сервиса, обычно HTTP. |

Если вы выберете обратный прокси Nginx HTTPS, сценарий будет повторно использовать существующий процесс сертификата `acme.sh + Cloudflare DNS API`, и сертификат все равно будет установлен в:

```text
/etc/caddy/certs/sub.example.com.crt
/etc/caddy/certs/sub.example.com.key
/root/cert/sub.example.com.crt
/root/cert/sub.example.com.key
```

`sub.example.com` — пример. Замените его фактическим доменом подписки. Обратный прокси Nginx HTTPS подходит только для схем без повторного использования порта 443. Если скрипт обнаружит повторное использование порта 443, он остановится, чтобы Nginx не занял публичный порт `443`. Не назначайте один домен одновременно Caddy и Nginx.

После настройки обратного прокси Caddy проверьте:

```bash
systemctl status caddy --no-pager
caddy validate --config /etc/caddy/Caddyfile
curl -I https://sub.example.com/
```

После настройки обратного прокси Nginx HTTPS проверьте:

```bash
nginx -t
systemctl status nginx --no-pager
curl -I https://sub.example.com/
```

При ответе 502:

```bash
curl -I http://127.0.0.1:3000/
journalctl -u caddy -n 80 --no-pager
journalctl -u nginx -n 80 --no-pager
```

В случае сбоя сертификата проверьте разрешения токена Cloudflare, зону авторизации, распространение TXT `_acme-challenge`, время сервера и журналы acme.sh. В сценарии используется DNS-01, а статус Orange Cloud не является непосредственной причиной сбоя выдачи.

### 4B. Вариант 2: Добавить сервис к повторному использованию порта 443

Используйте после включения:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [2 Первая настройка/установка повторное использование порта 443]
```

Чтобы позже добавить домен сервиса, не запускайте первоначальную настройку снова. Откройте:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]
```

Заполните пример:

| Проект | Пример |
|---|---|
| Новый Web-домен/обратный прокси | `sub.example.com` |
| Адрес бэкенда | `127.0.0.1` |
| Порт бэкенда | `3000` |

Для Docker-сервиса публикуйте порт контейнера на адресе хоста `127.0.0.1`, затем укажите этот порт хоста. Для другого сервера в частной сети указывайте его фактический IP-адрес или имя хоста только после проверки прямой доступности с этого VPS.

Скрипт обновит локальную конфигурацию Caddy или Nginx для выбранного Web-движка обратного прокси и выпустит сертификат. При подтверждении высокого риска проверьте снимок, DNS, токен и порт бэкенда, затем введите `YES` прописными буквами.

Если раньше был настроен отдельный Caddy/Nginx HTTPS в `Главное меню [4 Обратный прокси]`, при включении или повторном применении повторного использования порта 443 скрипт изолирует старую конфигурацию, которая может занять публичный `443`. В дальнейшем добавляйте домены сервисов через `[19] -> [8]`; не позволяйте Nginx HTTPS из `[4 Обратный прокси]` слушать публичный `443` напрямую.

Проверьте:

```bash
curl -I https://sub.example.com/
openssl s_client -connect серверIP:443 -servername sub.example.com </dev/null
```

### 5. Укажите внешний URL сервиса

Разные инструменты имеют разные названия. Общие поля включают в себя:

```text
External URL
Public URL
Base URL
ДОМЕН_ПОДПИСКИ
Внешний адрес доступа
```

Укажите публичный HTTPS-адрес:

```text
https://sub.example.com/
```

Не используйте:

```text
http://127.0.0.1:3000/
http://серверIP:3000/
https://sub.example.com:3000/
```

Если ссылка, созданная инструментом подписки, все еще содержит внутренний порт, клиент, возможно, не сможет его использовать.

### 6. Проверьте результат подписки

Откройте в браузере:

```text
https://sub.example.com/
```

Или выполните:

```bash
curl -I https://sub.example.com/
curl -L https://sub.example.com/ -o /tmp/sub-tool-home.html
```

При проверке результатов подписки обратите внимание на:

| Пункт | Ожидаемое значение |
|---|---|
| Домен | Публичный домен. |
| Протокол | HTTPS. |
| Порт | По умолчанию `443`, без внутреннего порта. |
| Token | Не попадает в публичные журналы. |
| Адрес узла | Не заменён на `127.0.0.1`. |

## Проверка

Если повторное использование порта 443 выключен, проверьте используемый обратный прокси Caddy или Nginx.

Caddy:

```bash
systemctl status caddy --no-pager
caddy validate --config /etc/caddy/Caddyfile
curl -I https://sub.example.com/
curl -I http://127.0.0.1:3000/
```

Nginx HTTPS обратный прокси:

```bash
systemctl status nginx --no-pager
nginx -t
curl -I https://sub.example.com/
curl -I http://127.0.0.1:3000/
```

Диагностика повторного использования порта 443:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]
```

Вы также можете сделать это вручную:

```bash
ss -lntp | grep -E ':443|:8443|:3000'
curl -I https://sub.example.com/
openssl s_client -connect серверIP:443 -servername sub.example.com </dev/null
```

Статус Docker:

```bash
docker ps
docker logs --tail=80 ИМЯ_КОНТЕЙНЕРА
```

## Откат после ошибки

| Проблема | Действие |
|---|---|
| Ошибка конфигурации Caddy | Восстановите копию Caddy либо изолируйте новую конфигурацию сайта и перезагрузите Caddy. |
| Ошибка обратного прокси Nginx HTTPS | Проверьте `nginx -t`; скрипт сохраняет конфигурацию в `/etc/nginx/conf.d/vps_proxy_${domain}.conf`. |
| Не удаётся добавить домен к повторному использованию порта 443 | Используйте автоматический откат из резервной копии или удалите домен в `Главное меню [19 Повторное использование порта 443] -> [8 Управление Web-доменами и обратным прокси]`. |
| Ошибка сертификата | В `Главное меню [19 Повторное использование порта 443] -> [12 Обслуживание сертификатов CF DNS / Caddy]` проверьте токен и DNS, затем перевыпустите сертификат. |
| Контейнер не запускается | Откройте меню управления соответствующим сервисом, проверьте состояние, перезапустите или пересоберите его. |
| Подписка содержит внутренний порт | Измените External URL или Public URL сервиса. |
| Порт открыт в Интернет | Ограничьте доступ через `Главное меню [11 Управление безопасностью Docker]` или `Главное меню [8 Правила межсетевого экрана]`. |
| Конфигурация стала несогласованной | Восстановите копию в `Главное меню [16 Резервное копирование и откат конфигурации] -> [3 Восстановить из резервной копии]`. |

## Распространённые проблемы

| Проблема | Симптом | Действие |
|---|---|---|
| Бэкенд недоступен | 502 | Запустите службу и убедитесь, что `curl http://127.0.0.1:порт/` или `curl http://ВНУТРЕННИЙ_АДРЕС:порт/` достигает фактического бэкенда. |
| DNS не разрешается на VPS | Домен не открывается либо ведёт на другой сервер | Исправьте запись A/AAAA и дождитесь распространения. |
| Для домена REALITY/узла включён прокси Cloudflare | Клиент не может подключиться к VPS напрямую | Переведите домен узла в DNS only; проксируйте Web-домены только при необходимости. |
| Повторная конфигурация домена | Caddy/Nginx работает нестабильно | Проверьте существующие сайты до добавления нового. |
| Прямой доступ к внутреннему порту | Угроза безопасности | Открывайте извне только HTTPS-домен. |
| В подписке указан `127.0.0.1` | Клиент не может использовать подписку | Укажите внешний URL. |
| При удалении контейнера данные считались сохранёнными | Риск потери данных | Перед остановкой или изоляцией проверьте каталог данных и тома Compose. |
