# Сервисы подписок с Caddy/Nginx на общем порту 443

В этом руководстве рассказывается о том, как безопасно предоставить HTTPS доступ к инструментам подписки, таким как SublinkPro, Sub-Store и Управление подписками Miaomiaowu. Если общая точка входа 443 не включен, вы можете использовать обратный прокси-сервер Caddy или Nginx HTTPS в `Главное меню [4 обратный прокси]`; после включения общей точки входа 443 вам следует перейти на точка входа имени веб-домена/обратного прокси общей точки входа 443 и выбрать на этом точка входае Caddy, Caddy или Caddy. Nginx действует как локальный механизм обратного веб-прокси.

Рекомендуемый выбор:

| Текущий статус | Рекомендуемый метод |
|---|---|
| Единый вход 443 еще не активирован. Я просто хочу сначала получить доступ к инструменту подписки. | `Главное меню [4 обратный прокси]`, выберите Caddy или Nginx HTTPS в соответствии с существующей средой. |
| общий вход 443 включен | `Главное меню [19 443 центр управления общим входом] -> [8 менеджмент Web домены / обратный прокси]` добавляет домен обратного прокси; используйте то же меню `[8 переключатель Web механизм обратного прокси]` для переключения между Caddy/Nginx, когда это необходимо. |
| Инструменты подписки предназначены только для вашего собственного использования. | Бэкэнд контролирует только локальный компьютер или адрес интрасети, и доступ к нему осуществляется извне через Caddy/Nginx или единый вход 443. |
| Не уверен, какой из них выбрать | Сначала запустите `Главное меню [1 Предварительная проверка и анализ рисков]` и `Главное меню [15 Обзор состояния служб]`, чтобы подтвердить статус порта и службы. |

## Что будет изменено?

| Проект | Содержимое может быть изменено | риск |
|---|---|---|
| Docker/Compose | Добавляйте новые контейнеры, сети и каталоги развертывания. | Конфликт порта контейнера или сбой получения образа |
| Caddy | Добавлена конфигурация сайта, сертификаты и правила обратный прокси. | Ошибки конфигурации могут вызвать ошибку 404/502. |
| Nginx HTTPS обратный прокси | Если единый вход 443 не включен, можно добавить конфигурацию сайта HTTPS. | Ошибки конфигурации или конфликты портов могут вызвать исключения доступа 80/443. |
| Nginx stream | Если вы получите доступ к общему входу 443, будет добавлен маршрут SNI. | Ошибки конфигурации могут повлиять на публичный порт `443` |
| брандмауэр | Рекомендуется предоставлять доступ только к входному порту, а не к внутреннему порту. | Неправильная версия может привести к раскрытию внутренних служб. |
| резервное копирование | Создание каталогов резервного копирования и карантина конфигурации. | Занимает небольшой объем диска |

Введите:

```text
Главное меню [1 Предварительная проверка и анализ рисков]
```

Ключевые моменты для подтверждения:

| Проект | Ожидание |
|---|---|
| Docker | Если он не установлен, процесс установки средства подписки установит его автоматически. |
| Порт занят | Порт инструмента подписки не должен конфликтовать с существующими службами. |
| DNS | Подписанное домен может быть преобразовано в текущий VPS. |
| брандмауэр | SSH и входящий порт освобождены. |
| системное время | Выдача сертификата требует точного времени |

Проверьте порт вручную:

```bash
ss -lntp
```

### 2. Установите инструмент подписки.

Введите:

```text
Главное меню [5 панель、Узлы и инструменты подписки]
```

В процессе установки автоматически проверяются Docker/Compose и устанавливаются первыми, если они отсутствуют.

Общие входы:

| Управление подпиской Miaomiaowu | `Главное меню [5 панель、Узлы и инструменты подписки] -> [8 стек подписок Miaomiaowu]` | Графическое управление подписками |
| Sub-Store | `Главное меню [5 панель、Узлы и инструменты подписки] -> [9 Sub-Store стек подписок]` | Расширенная обработка подписок и создание сценариев |

```bash

```

### 3. Подтвердите метод привязки серверной части.

Рекомендуется, чтобы бэкенд инструмента подписки была привязана только к локальной или интрасети, и не рекомендуется напрямую подключаться к Интернету. Ниже приведены примеры значений:

```text
127.0.0.1:3000
10.0.0.20:3000
```

Проверьте:

Выберите соответствующую команду в соответствии с фактическим адресом серверной части.

```bash
ss -lntp | grep -E ':3000|:3001|:3002'
curl -I http://127.0.0.1:3000/
curl -I http://10.0.0.20:3000/
```

Если бэкенд привязана к `0.0.0.0:3000`, это означает, что Интернет может быть доступен напрямую. Вы можете ограничить воздействие с помощью локальной защиты от проникновения Docker или брандмауэра:

```text
Главное меню [11 Docker Управление безопасностью]
Главное меню [8 Правила брандмауэра]
```

Защита от проникновения Docker изменит поведение сети Docker и перезапустит Docker, что представляет собой операцию с высоким риском. Прежде чем продолжить, убедитесь, что контейнер не использует порт прямого подключения к Интернету.

### 4А. Вариант 1. Используйте обратный прокси-сервер Caddy/Nginx, когда общий вход 443 не включен.

Он подходит для тех, кто еще не включил однократную запись 443 и просто хочет сначала использовать домен для доступа к инструменту подписки.

Введите:

```text
Главное меню [4 обратный прокси]
```

Выберите в соответствии с текущей средой:

| вход | Подходит для ситуации |
|---|---|
| `[1 добавить Caddy обратный прокси]` | Уже используете Caddy или хотите, чтобы сайт управлялся напрямую с помощью Caddy? |
| `[2 добавить Nginx HTTPS обратный прокси]` | Общий вход 443 не включен, и есть надежда, что Nginx будет напрямую подключен к Интернету 80/443 для предоставления HTTPS. |

Заполните пример, замените имя домена и порт своими фактическими значениями:

| Проект | Пример |
|---|---|
| домен | `sub.example.com` |
| внутренний порт | `3000` |
| серверный протокол | В зависимости от фактической ситуации с инструментом, обычно HTTP. |

Если вы выберете обратный прокси Nginx HTTPS, сценарий будет повторно использовать существующий процесс сертификата `acme.sh + Cloudflare DNS API`, и сертификат все равно будет установлен в:

```text
/etc/caddy/certs/sub.example.com.crt
/etc/caddy/certs/sub.example.com.key
/root/cert/sub.example.com.crt
/root/cert/sub.example.com.key
```

`sub.example.com` — пример. Замените его фактическим доменом подписки. Обратный прокси Nginx HTTPS подходит только для схем без общего входа 443. Если скрипт обнаружит общий вход 443, он остановится, чтобы Nginx не занял публичный порт `443`. Не назначайте один домен одновременно Caddy и Nginx.

Если вы используете Caddy для обратный прокси, проверьте после настройки:

```bash
systemctl status caddy --no-pager
caddy validate --config /etc/caddy/Caddyfile
curl -I https://sub.example.com/
```

Если вы используете Nginx HTTPS для обратный прокси, проверьте после настройки:

```bash
nginx -t
systemctl status nginx --no-pager
curl -I https://sub.example.com/
```

Если 502:

```bash
curl -I http://127.0.0.1:3000/
journalctl -u caddy -n 80 --no-pager
journalctl -u nginx -n 80 --no-pager
```

В случае сбоя сертификата проверьте разрешения токена Cloudflare, зону авторизации, распространение TXT `_acme-challenge`, время сервера и журналы acme.sh. В сценарии используется DNS-01, а статус Orange Cloud не является непосредственной причиной сбоя выдачи.

### 4Б. Вариант 2: Доступ к единому входу 443

Подходит для уже включенных:

```text
Главное меню [19 443 центр управления общим входом] -> [2 Первая настройка/установка 443 единственный вход]
```

Если вы добавите новое домен средства подписки позже, не повторяйте первую конфигурацию. Введите:

```text
Главное меню [19 443 центр управления общим входом] -> [8 менеджмент Web домены / обратный прокси]
```

Заполните пример:

| Проект | Пример |
|---|---|
| Новый веб-сайт/обратное домен | `sub.example.com` |
| Внутренний адрес | `127.0.0.1` |
| внутренний порт | `3000` |

Служба Docker рекомендует опубликовать порт контейнера на хосте `127.0.0.1`, а затем заполнить соответствующий порт хоста. При подключении к другим серверам интрасети вы можете указать фактический IP-адрес интрасети или имя хоста, но сначала вы должны подтвердить, что к текущему VPS возможен прямой доступ.

Скрипт обновит локальную конфигурацию Caddy или Nginx в соответствии с текущим механизмом веб-обратный прокси и подаст заявку на получение сертификата. При возникновении подтверждения высокого риска убедитесь, что снимок, DNS, токен и внутренний порт верны, прежде чем вводить `YES` в верхнем регистре.

Если вы ранее настроили независимый обратный прокси-сервер Caddy/Nginx HTTPS на `Главное меню [4 обратный прокси]`, то при включении или повторном применении общей записи 443 сценарий изолирует старую конфигурацию, которая может захватить Интернет `443`. В будущем домен инструмента подписки должно быть добавлено из `[19] -> [8]`, а обратный прокси-сервер Nginx HTTPS из `[4 обратный прокси]` не должен быть напрямую привязан к Интернету `443`.

Проверьте:

```bash
curl -I https://sub.example.com/
openssl s_client -connect серверIP:443 -servername sub.example.com </dev/null
```

### 5. Настройте внешний адрес доступа инструмента подписки.

Разные инструменты имеют разные названия. Общие поля включают в себя:

```text
External URL
Public URL
Base URL
ДОМЕН_ПОДПИСКИ
Внешний адрес доступа
```

Интернет-адрес HTTPS необходимо заполнить:

```text
https://sub.example.com/
```

Не заполняйте:

```text
http://127.0.0.1:3000/
http://серверIP:3000/
https://sub.example.com:3000/
```

Если ссылка, созданная инструментом подписки, все еще содержит внутренний порт, клиент, возможно, не сможет его использовать.

### 6. Проверьте содержимое подписки.

Браузер открывается:

```text
https://sub.example.com/
```

Проверка команды:

```bash
curl -I https://sub.example.com/
curl -L https://sub.example.com/ -o /tmp/sub-tool-home.html
```

При проверке результатов подписки обратите внимание на:

| Проект | Ожидание |
|---|---|

| соглашение | HTTPS |

## Метод проверки

Обратный прокси-сервер Caddy/Nginx общего входа 443 не включен, проверьте его в соответствии с фактически используемым входом.

Caddy：

```bash
systemctl status caddy --no-pager
caddy validate --config /etc/caddy/Caddyfile
curl -I https://sub.example.com/
curl -I http://127.0.0.1:3000/
```

Nginx HTTPS обратный прокси:

```bash
systemctl status nginx --no-pager
nginx -t
curl -I https://sub.example.com/
curl -I http://127.0.0.1:3000/
```

443 Проверка меню общей записи:

```text
Главное меню [19 443 центр управления общим входом] -> [13 443 Проверка соединения]
```

Вы также можете сделать это вручную:

```bash
ss -lntp | grep -E ':443|:8443|:3000'
curl -I https://sub.example.com/
openssl s_client -connect серверIP:443 -servername sub.example.com </dev/null
```

Статус Docker:

```bash
docker ps
docker logs --tail=80 ИМЯ_КОНТЕЙНЕРА
```

## Как откатиться, если не удалось

| вопрос | Процесс |
|---|---|
| Ошибка конфигурации Caddy | Используйте резервное копирование и восстановление Caddy или изолируйте новую конфигурацию сайта, а затем перезагрузите ее. |
| Nginx HTTPS Ошибка конфигурации обратного прокси-сервера | Проверьте вывод `nginx -t`; созданная скриптом конфигурация обратный прокси Nginx будет помещена в `/etc/nginx/conf.d/vps_proxy_${domain}.conf` |
| 443 Не удалось добавить домен в одну запись. | Используйте скрипты для автоматизации отката резервной копии или удаления домена из `Главное меню [19 443 центр управления общим входом] -> [8 менеджмент Web домены / обратный прокси]`. |
| Сертификат не удался | `Главное меню [19 443 центр управления общим входом] -> [12 CF DNS / Caddy Обслуживание сертификатов]` Check Token, DNS, переподписать |
| Запуск контейнера не удался | Войдите в соответствующее меню управления инструментом, чтобы просмотреть состояние, перезапустить или перестроить |
| Подписаться на выходной внутренний порт | Инструменты изменения Внешний URL-адрес / Публичный URL-адрес |
| Порт, доступный в Интернет | `Главное меню [11 Docker Управление безопасностью]` или `Главное меню [8 Правила брандмауэра]` ограничить доступ |
| Общая конфигурация сбивает с толку | `Главное меню [16 Резервное копирование и откат конфигурации] -> [3 Восстановить из резервной копии]` Восстановление из резервной копии |

## Распространенные ошибки

| Ошибка | явление | Процесс |
|---|---|---|
| бэкенд не может быть подключена | 502 | Сначала запустите службу, а затем подтвердите, что `curl http://127.0.0.1:порт/` или `curl http://ВНУТРЕННИЙ_АДРЕС:порт/` доступен в соответствии с фактическим сервером. |
| DNS не разрешил VPS | домен не открывается или используется неправильный сервер. | Исправьте запись A/AAAA и подождите, пока она вступит в силу. |
