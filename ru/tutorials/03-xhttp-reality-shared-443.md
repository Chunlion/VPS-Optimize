# REALITY и xhttp вместе: отдельный домен или общий 443

Это руководство описывает добавление узлов xhttp на сервер, где уже работает повторное использование порта 443, и их совместную работу с узлами REALITY.

Выберите одну из двух схем. Смешивать их нельзя:

| Вариант | Публичный вход | Где завершается TLS | Когда подходит |
| --- | --- | --- | --- |
| A. Отдельный домен узла | Вход передаёт по SNI на локальный вход xhttp | На входе xhttp | Один отдельный узел, минимум настроек |
| B. Общий Web-домен | Вход передаёт по SNI в Caddy/Nginx, который проксирует по пути к xhttp | На локальном Caddy/Nginx | Узел и панель/сайт на одном домене и одном `443` |

## Что нужно заранее

- Повторное использование порта 443 уже настроено по [руководству](../docs/443-single-entry.md), и `ss -lntp | grep ':443'` показывает один слушатель входа.
- Режим входа — `nginx-stream` или `tcp-peek`. В `xray-fallback` публичный вход занимает основной вход Xray, поэтому описанные меню недоступны.
- Панель 3x-ui и подписка по-прежнему работают на локальных HTTP-портах.
- Не закрывайте текущий сеанс SSH и сначала сделайте резервную копию конфигурации.

## Вариант A: отдельный домен узла

Подходит, когда домен вроде `xhttp.example.com` используется только для узлов.

### 1. Подготовьте сертификат

TLS завершается на самом входе xhttp, поэтому сертификат должен покрывать домен узла. Файлы размещаются там, где их ожидает повторное использование порта 443:

```text
/etc/caddy/certs/xhttp.example.com.crt
/etc/caddy/certs/xhttp.example.com.key
```

Перевыпустите сертификат существующим скриптом или выпустите его самостоятельно для того же домена и путей. Не кладите ключ в каталог, доступный из Web.

### 2. Создайте вход xhttp в 3x-ui

| Поле | Значение |
| --- | --- |
| Адрес прослушивания | `127.0.0.1` |
| Порт прослушивания | Свободный локальный порт, например `2410` |
| Протокол | VLESS (или тот, который вы используете) |
| Транспорт / network | `xhttp` (в старых сборках может отображаться `splithttp`) |
| Путь xhttp | Запомните его, например `/xhttp` |
| Host | Необязательно; если указан, должен быть `xhttp.example.com` |
| Безопасность | `tls` |
| Пути сертификата | Два файла из предыдущего шага |
| ALPN | `h2,http/1.1` или как в клиенте |

Вход должен слушать `127.0.0.1`. Привязка к `0.0.0.0` открывает локальный порт напрямую и обходит вход `443`.

### 3. Зарегистрируйте маршрут SNI в скрипте

```text
Главное меню [19 Повторное использование порта 443] -> [4 Управлять правилами передачи Xray SNI] -> [2 Добавить маршрут SNI]
```

- SNI входа: `xhttp.example.com`
- Локальный адрес: `127.0.0.1`
- Локальный порт: `2410`

После сохранения скрипт спросит, применить ли изменения к текущему входу. Ответьте утвердительно.

### 4. Клиент

```text
Адрес: xhttp.example.com
Порт: 443
Транспорт: xhttp
path: /xhttp
TLS: включён
SNI / serverName: xhttp.example.com
```

`path` клиента должен полностью совпадать с входом. Вход только передаёт TCP и не читает путь, поэтому конфликтов путей здесь не бывает.

## Вариант B: общий порт 443 с Web-доменом

Подходит, когда узел и панель или сайт должны отвечать на одном домене:

```text
https://panel.example.com/panel/   -> панель 3x-ui
https://panel.example.com/xhttp    -> узел xhttp
```

### 1. Создайте вход xhttp без TLS в 3x-ui

| Поле | Значение |
| --- | --- |
| Адрес прослушивания | `127.0.0.1` |
| Порт прослушивания | Например `2400` |
| Транспорт / network | `xhttp` |
| Путь xhttp | Например `/xhttp` |
| Host | Необязательно; если указан, должен быть доменом панели или сайта |
| Безопасность | `none` |

Главное: **не включайте TLS на этом входе**. TLS завершается на Caddy/Nginx на локальном `8443`, а вход принимает только открытый HTTP. TLS с обеих сторон всегда приводит к ошибке рукопожатия.

### 2. Зарегистрируйте обратный прокси пути в скрипте

```text
Главное меню [19 Повторное использование порта 443] -> [2 Управлять Web-доменами и обратным прокси] -> [10 Обратный прокси пути xhttp] -> [2 Добавить правило пути xhttp]
```

Заполните:

| Запрос | Пример |
| --- | --- |
| Web-домен для xhttp | `panel.example.com` |
| Путь xhttp | `/xhttp` |
| Локальный адрес | `127.0.0.1` |
| Локальный порт | `2400` |

Скрипт проверяет:

- Домен уже должен существовать как домен панели или Web-домен, чтобы сертификат и Web-вход были готовы.
- Путь не должен пересекаться с `webBasePath` панели, путями подписки и путём Clash. Пересечение префиксов вроде `/panelx` тоже отклоняется, потому что Nginx сопоставляет по префиксу.
- Локальный порт должен прослушиваться и отличаться от портов входа, Web-прокси, панели и подписки.

Подтвердите повторное применение: скрипт заново создаст конфигурацию Caddy или Nginx и перезапустит Web-службу.

### 3. Клиент

```text
Адрес: panel.example.com
Порт: 443
Транспорт: xhttp
path: /xhttp
TLS: включён
SNI / serverName: panel.example.com
```

Клиент подключается к Web-домену и использует существующий сертификат панели или сайта. Дополнительный сертификат не нужен.

## Как выбрать

| Вопрос | Вариант A | Вариант B |
| --- | --- | --- |
| Есть отдельный домен узла? | Да | Не нужен |
| Один домен для узла и панели? | Невозможно | Да |
| Меньше сертификатов в обслуживании? | Нет | Да |
| Планируется CDN? | Зависит от поддержки протокола | Подходит лучше, сначала проверьте на сером облаке |
| Настроить один раз и забыть? | Да | Нет |

Узлы REALITY не зависят от выбранного варианта: они продолжают использовать свои маршруты SNI и не затрагивают правила путей xhttp.

## Ограничения

- **Нет HTTP/3**: режим QUIC в xhttp требует UDP `443`, а вход слушает только TCP `443`.
- **Недоступно в xray-fallback**: в этом режиме нет отдельного Web-слоя, поэтому `[2] -> [10]` сообщает о недоступности. Настраивайте xhttp в `fallbacks` основного входа.
- **Белый список Web ограничивает и xhttp**: правила варианта B находятся под Web-доменом, поэтому белый список IP для этого домена действует и на xhttp. REALITY и маршруты SNI варианта A не затрагиваются.
- **Фильтрация SNI работает по домену**: вариант B не добавляет новый SNI, домен уже в списке. В варианте A домен узла нужно зарегистрировать как маршрут SNI, иначе строгая фильтрация его отклонит.
- **Долгие соединения xhttp**: скрипт отключает буферизацию ответа и запроса для прокси пути и задаёт таймаут чтения/записи 1 час. Не добавляйте короткий таймаут в Web-прокси.

## Проверка

Сначала проверьте слушатели:

```bash
ss -lntp | grep -E ':(443|2400|2410)'
```

Ожидается: `443` принадлежит активной службе входа; `2400` и `2410` принадлежат Xray и привязаны к `127.0.0.1`.

Для варианта B проверьте, доходит ли путь до входа xhttp:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://panel.example.com/xhttp
```

Код 404 или 400 здесь нормален: запрос дошёл до входа xhttp, а не до панели. Если вернулась HTML-страница входа панели или 502, правило пути не действует или порт неверен:

```bash
curl -sS -D - -o /dev/null https://panel.example.com/xhttp | head -20
curl -sS http://127.0.0.1:2400/xhttp -o /dev/null -w '%{http_code}\n'
```

Сравните код и заголовки. Если они различаются, проблема на уровне Web-прокси. Если совпадают, но клиент не подключается, проблема во входе или параметрах клиента.

В конце подключитесь реальным клиентом. Проверка TLS и портов не заменяет настоящую сессию xhttp.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Рукопожатие прошло, данных нет | Совпадение пути входа и клиента; лишний или пропущенный завершающий слэш |
| Вариант B возвращает страницу входа панели | Правило пути не активно: подтвердите повторное применение и проверьте пересечение с `webBasePath` |
| Вариант B возвращает 502 | Локальный вход xhttp не слушает или порт неверен; проверьте прямым `curl` |
| Вариант A: ошибка рукопожатия | Сертификат не покрывает домен узла или на входе выключен TLS |
| Вариант B: ошибка рукопожатия | На входе включён TLS, а локальный бэкенд работает по HTTP |
| Вход отбрасывает узел | В варианте A не зарегистрирован маршрут SNI или он не применён к текущему входу |
| Web работает, узел нет | У домена включён белый список IP; добавьте IP клиента или перейдите на вариант A |

Журналы:

```bash
journalctl -u caddy -n 80 --no-pager     # вариант B, движок Caddy
journalctl -u nginx -n 80 --no-pager     # вариант B, движок Nginx
journalctl -u x-ui -u 3x-ui -n 80 --no-pager
```

## Чего не делать

- Не включайте TLS на входе, который обслуживается прокси варианта B по открытому HTTP.
- Не привязывайте локальный порт xhttp к `0.0.0.0`.
- Не размещайте путь xhttp на `/panel/`, `/sub/`, `/clash/` или их подпутях.
- Не пытайтесь управлять путями через `[2] -> [10]` в режиме `xray-fallback`.
- Не развёртывайте с примерными доменами и портами.
