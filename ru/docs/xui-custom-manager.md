# Руководство по расширению x-ui


## Функциональное позиционирование

`xui-custom-manager.sh` — это сценарий пакета расширений x-ui, который не заменяет ни программу 3x-ui, ни саму панель 3x-ui. Он используется для дополнения некоторых функций обслуживания, более подходящих для сценариев:

- Дата сброса пользовательского трафика.
- Входящий индивидуальный день сброса.
- Дата сброса клиента индивидуально.
- Предварительный просмотр `reset-check`.
- Калибровка потока.
- Резервное копирование/восстановление базы данных.
- Резервное копирование/восстановление каталога конфигурации и каталога программы.
- `systemd timer` автоматическая проверка.
- Проверка работоспособности, просмотр журналов и очистка старых резервных копий.

Важный риск: инструмент поддерживает только развёртывания с SQLite и напрямую читает и записывает базу SQLite 3x-ui `/etc/x-ui/x-ui.db`. Перед записью создайте снимок VPS и резервную копию базы данных.

## Граница совместимости версий

Поддерживает 3x-ui 2.9.x и 3.x с SQLite. Перед записью должна пройти проверка схемы только для чтения, а необходимые таблицы и поля должны остаться без изменений.

PostgreSQL не поддерживается. Не используйте инструмент для чтения или записи базы 3x-ui, если `XUI_DB_TYPE` в `/etc/default/x-ui`, `/etc/sysconfig/x-ui` или `/etc/conf.d/x-ui` имеет значение `postgres`, `postgresql` или `pg`.

Другие версии 3x-ui не поддерживаются. Если версия не находится в поддерживаемом диапазоне или проверка схемы не удалась, рекомендуется выполнить только:

- Резервное копирование.
- Посмотреть конфигурацию.
- Проверка здоровья.
- Предварительный просмотр.
- Самопроверка.

Не записывайте библиотеку принудительно, пропуская диапазоны версий и проверки схемы. Если сценарий сообщит, что текущая версия не поддерживается или поля базы данных несовместимы, прекратите запись базы данных и сначала сохраните резервную и диагностическую информацию.

## Что нужно сделать перед бегом

1. Создайте снимок VPS.
2. Убедитесь, что используется SQLite, затем создайте резервную копию `/etc/x-ui/x-ui.db`.
3. Убедитесь, что текущая версия 3x-ui принадлежит версии 2.9.x или 3.x.
4. Убедитесь, что соответствующий входящий собственный сброс `monthly` на панели 3x-ui отключен или изменен на `never` / без сброса.
5. Сохраните текущий сеанс SSH.
6. Сначала выполните предварительный просмотр, не выполняйте реальный сброс напрямую.
7. Если вы только что отредактировали базу данных вручную, сначала выполните предварительный просмотр и самопроверку, чтобы убедиться, что конфигурация совместима с полями.

## Беги быстро

Запустите на сервере под именем `root`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chunlion/VPS-Optimize/main/xui-custom-manager.sh)
```

Для сценария требуются разрешения `root`, поскольку он имеет доступ к `/etc/x-ui`, каталогу резервных копий, каталогу журналов и модулю systemd. Команды быстрого доступа будут зарегистрированы после первого открытия:

```bash
xcm
```

Часто используемые команды:

```bash
xcm
bash /usr/local/bin/xui-custom-manager.sh --reset-check --dry-run
bash /usr/local/bin/xui-custom-manager.sh --self-test
```

## Пользовательская логика сброса

Пользовательский сброс контролируется `/etc/xui-custom-reset.json`, основная концепция заключается в следующем:

- Глобальное включение/отключение: если глобально отключено, автоматическая проверка пропускает реальный сброс.
- Дата сброса по умолчанию: Входящие соединения без отдельных настроек могут использовать дату по умолчанию.
- День входящего индивидуального сброса: вы можете установить день месяца для определенного входящего сброса.
- Дата сброса, независимая от клиента: для клиента можно установить независимую дату.
- Следуют ли клиенты, даты которых не установлены индивидуально, за входящим: контролируется соответствующими правилами входящего подключения.
- Сбрасывается ли входящий сам `up/down`: контролируется соответствующими правилами входящего подключения.

Диапазон дат: 1–31. Если дата месяца превышает количество дней в месяце, она будет считаться последним днем ​​месяца. Например, если установлено 31-е число, февраль будет считаться последним днем ​​февраля.

При использовании внешнего пользовательского сброса не включайте одновременно встроенный 3x-ui `monthly` и внешний пользовательский сброс, чтобы избежать повторных сбросов или трудностей с определением статуса.

## Написание описания поведения библиотеки

Реальное выполнение изменит поле используемого трафика в базе данных 3x-ui:

- Входящие: `inbounds.up`, `inbounds.down`.
- Клиент: `client_traffics.up`, `client_traffics.down`.

Реальное выполнение не изменит ограничение трафика `total`. Клиент будет повторно включен в соответствии с официальной логикой. Скрипт запишет состояние сброса, чтобы указать, было ли оно выполнено в этом месяце, чтобы избежать повторных сбросов в том же месяце.

Перед записью в базу данных будет автоматически создана резервная копия. `x-ui` будет остановлен и перезапущен во время выполнения, чтобы уменьшить конфликты между записью в базу данных и запуском службы. Пожалуйста, проверьте журнал и состояние панели после выполнения.

В режиме предварительного просмотра не производится запись в базу данных, остановка или запуск `x-ui`, а также запись состояния сброса.

## Инструкции по калибровке расхода

Калибровка расхода используется для ручного изменения используемого расхода в базе данных:

- Входящая калибровка изменяет `inbounds.up`/`inbounds.down`.
- Клиентская калибровка изменит `client_traffics.up`/`client_traffics.down`.

Калибровка не изменяет верхний предел `total`. Перед записью будут отображаться значения до и после модификации. Вы должны ввести `YES` для записи в библиотеку. Перед записью будет автоматически создана резервная копия базы данных, а после записи будет предпринята попытка запуска `x-ui`.

Если версия выходит за пределы поддерживаемого диапазона или проверка схемы не удалась, использование реальной калибровки библиотеки записи запрещено.

## автоматический таймер

Если включен пользовательский сброс, скрипт устанавливает или обновляет:

- `xui-custom-reset.service`
- `xui-custom-reset.timer`

Таймер по умолчанию запускается один раз в день по адресу `00:10`:

```text
OnCalendar=*-*-* 00:10:00
```

выполнение услуги:

```text
/usr/bin/env bash /usr/local/bin/xui-custom-manager.sh --reset-check
```

Просмотр состояния таймера:

```bash
systemctl status xui-custom-reset.timer --no-pager
```

Просмотрите журнал автоматической проверки:

```bash
journalctl -u xui-custom-reset.service -n 100 --no-pager
tail -n 100 /var/log/xui-custom-manager.log
```

Таймер можно включить или отключить в меню. Таймер не должен автоматически устанавливаться или включаться, если версия не поддерживается или проверка схемы не удалась.

## путь к файлу

| путь | Описание |
|---|---|
| `/etc/xui-custom-manager.conf` | Профиль конфигурации внешнего менеджера |
| `/etc/xui-custom-reset.json` | Конфигурация пользовательского правила сброса |
| `/root/x-ui-backups` | База данных, каталог конфигурации, каталог резервного копирования каталога программы |
| `/etc/x-ui/x-ui.db` | 3x-ui База данных SQLite |
| `/var/log/xui-custom-manager.log` | Журнал внешнего менеджера |
| `/var/lib/xui-custom-manager/reset-state.json` | Сбрасывать файл состояния ежемесячно |
| `/etc/systemd/system/xui-custom-reset.service` | Автоматически проверять сервис |
| `/etc/systemd/system/xui-custom-reset.timer` | Автоматически проверять таймер |
| `/usr/local/bin/xui-custom-manager.sh` | местный стабильный привод |
| `/usr/local/bin/xcm` | Ручной быстрый ввод |

## Резервное копирование и восстановление

Скрипт поддерживает резервное копирование:

- База данных `/etc/x-ui/x-ui.db`.
- Каталог конфигурации `/etc/x-ui`.
- Каталог программы `/usr/local/x-ui`.

Перед восстановлением текущее состояние будет снова скопировано. Восстановление перезапишет текущую базу данных, каталог конфигурации или каталог программы, поэтому перед выполнением вы должны убедиться, что источник файла резервной копии надежен, и сохранить снимки VPS или другие средства отката.

Старая очистка резервной копии должна удалять только явно выбранные файлы. Не удаляйте каталоги резервных копий массово.

## Устранение неполадок

### База данных не существует

Убедитесь, что 3x-ui использует SQLite и путь к базе — `/etc/x-ui/x-ui.db`. Для другого файла SQLite задайте `XUI_DB` в `/etc/xui-custom-manager.conf`. PostgreSQL не поддерживается; не записывайте базу с непроверенной схемой.

### Поля базы данных несовместимы

Перестаньте писать в библиотеку. Не гадайте о структуре поля. Вы можете выполнять резервное копирование, просмотр, предварительный просмотр, самопроверку и сохранять выходные данные об ошибках для устранения неполадок.

### Текущая версия 3x-ui не поддерживается.

Не выполняйте функцию записи библиотеки. Рекомендуется выполнять только резервное копирование, просмотр, предварительный просмотр и самотестирование. Не включайте таймер принудительно и не выполняйте настоящую запись `reset-check` или калибровки потока в библиотеку.

### таймер не работает

Проверьте:

```bash
systemctl status xui-custom-reset.timer --no-pager
systemctl list-timers | grep xui-custom-reset
```

Убедившись, что текущая версия 3x-ui — 2.9.x или 3.x и проверка схемы пройдена, включите автоматическую проверку из меню.

### сброс-проверка не выполняется

Сначала запустите предварительный просмотр:

```bash
bash /usr/local/bin/xui-custom-manager.sh --reset-check --dry-run
```

Посмотрите еще раз лог:

```bash
journalctl -u xui-custom-reset.service -n 100 --no-pager
tail -n 100 /var/log/xui-custom-manager.log
```

### Конфигурация JSON повреждена.

Проверьте, является ли `/etc/xui-custom-reset.json` законным JSON. В случае повреждения сначала создайте резервную копию текущего файла, а затем восстановите его из `/root/x-ui-backups` или снимка VPS.

### Поврежденный файл состояния

Файл состояния — `/var/lib/xui-custom-manager/reset-state.json`. Не перезаписывайте производственный статус напрямую в случае повреждения. Сначала создайте резервную копию текущего файла, а затем используйте журнал и базу данных, чтобы подтвердить, был ли выполнен сброс в этом месяце, чтобы избежать повторных сбросов.

### Не удалось записать библиотеку

Не повторяйте фактическое написание библиотеки. Проверьте разрешения базы данных, совместимость полей, дисковое пространство, можно ли остановить/запустить `x-ui` и был ли создан файл резервной копии. Сохраните журналы, прежде чем принимать решение о восстановлении резервной копии.

### x-ui Не удалось перезапустить

Просмотр состояния и журналов службы:

```bash
systemctl status x-ui --no-pager
journalctl -u x-ui -n 100 --no-pager
```

Если резервная копия базы данных была создана до фактической записи в базу данных, резервную копию можно восстановить в зависимости от ситуации сбоя. Перед восстановлением подтвердите, что текущие данные будут перезаписаны.

## Запрещенные дела

- Не выполняйте функцию записи базы данных без резервного копирования базы данных.
- Не записывайте библиотеку принудительно, пропуская диапазоны версий и проверки схемы.
- Не включайте одновременно встроенный 3x-ui `monthly` и внешний пользовательский сброс.
- Не запускайте настоящий сброс сразу после редактирования базы данных вручную, сначала выполните предварительный просмотр и самопроверку.
- Не тестируйте функцию записи на производственной машине без моментального снимка VPS или резервной копии базы данных.
