# Настройка повторного использования порта 443

При проблемах с панелью, подпиской, сертификатом или подключением REALITY сначала откройте [Диагностика повторного использования порта 443](443-single-entry-troubleshooting.md).

В этом документе рассказывается, как подключить Интернет-VPS `443` к повторному использованию порта 443 VPS-Optimize. По умолчанию рекомендуется использовать Nginx Stream. Вы также можете переключиться на TCP Peek + Splice или Xray Fallback после завершения настройки. Независимо от того, какой режим входа выбран, Интернет `443` одновременно привязан только к одной услуге, соответствующей текущему `ENTRY_MODE`.

Текущая ссылка на повторное использование порта 443:

```text
Публичный порт 443 -> служба повторного использования порта 443 для текущего ENTRY_MODE
  nginx-stream  -> nginx маршрутизация по SNI
  tcp-peek      -> vpso-mux маршрутизация по SNI
  xray-fallback -> Xray основное входящее подключение принимает порт 443, И fallback Обычный HTTPS

Обычный HTTPS / Web домен -> текущий выбранный локальный Web механизм обратного прокси (Caddy или Nginx)-> Доступно для этой машины HTTP бэкенд
3x-ui Панель -> Текущий выбранный локальный Web механизм обратного прокси -> 127.0.0.1:40000
3x-ui Подписка -> Текущий выбранный локальный Web механизм обратного прокси -> 127.0.0.1:2096
REALITY / Xray SNI    -> локальное входящее подключение Xray / 3x-ui -> 127.0.0.1:1443
```

`127.0.0.1:40000`, `127.0.0.1:2096` и `127.0.0.1:1443` на рисунке — это всего лишь примеры значений. Преимущество этого заключается в том, что только один `443` доступен в Интернете, обычный HTTPS попадает в выбранный в данный момент локальный механизм обратного веб-прокси (Caddy или Nginx), а сертификат применяется и устанавливается VPS-Optimize с использованием `acme.sh + Cloudflare DNS API`. Панель 3x-ui и служба подписки используют только собственный бэкэнд HTTP. Автономный сертификат 3x-ui не используется в качестве окончательного решения для интернет-сертификата во избежание дублирования HTTPS, конфликтов портов, петель перенаправления и путаницы в пути сертификата.

Недавно добавленные веб-сайты/обратные прокси-серверы по умолчанию используют бэкенд `127.0.0.1`. Служба Docker рекомендует опубликовать порт контейнера по адресу обратной связи хоста, а затем заполнить соответствующий порт хоста; Заполняйте собственный внутренний адрес только в том случае, если текущий VPS действительно может разрешить и получить доступ к IP-адресу или имени хоста интрасети. Перед сохранением скрипт проверит, доступен ли бэкенд. В случае неудачи перед продолжением требуется явное подтверждение. Не открывайте внутренний порт напрямую в Интернет.

| Проект | Пример документации | ваша фактическая стоимость |

| домен сайта | site.example.com | Пожалуйста, измените его на свой |

## Посмотрите сначала на эту таблицу

| компоненты | позиция прослушивания | Обязанности |
| --- | --- | --- |
| Nginx stream | `0.0.0.0:443` | Режим входа по умолчанию, маршрутизирует по SNI |
| vpso-mux | `0.0.0.0:443` | Запись режима TCP Peek + Splice, выберите один из Nginx Stream |
| Xray/3x-ui основной входящий | `0.0.0.0:443` | Xray Вход в резервный режим, выберите один из первых двух |
| Caddy или Nginx обратный прокси локальной сети | `127.0.0.1:8443` | Управляемые веб-сертификаты, панели обратного прокси, подписки и веб-сайты |
| Панель 3x-ui | `127.0.0.1:40000` | Собственный бэкэнд HTTP не использует собственный сертификат в качестве интернет-сертификата HTTPS. |
| 3x-ui Подписаться | `127.0.0.1:2096` | Собственный бэкэнд HTTP, проксируемый механизмом обратного веб-прокси в Интернет HTTPS |
| REALITY / Xray местный входящий | `127.0.0.1:1443` | Пересылается входом как SNI в режиме Nginx Stream или TCP Peek. |

Основные принципы:

1. Публичная сеть `443` одновременно обеспечивает только один входной процесс: `nginx`, `vpso-mux` или Xray в качестве основного входящего процесса.
2. Локальный веб-сервер Caddy или Nginx отвечает за панели и подписки браузера HTTPS, 3x-ui только как локальный сервер HTTP.
3. REALITY `dest` / `Target` и `serverNames` / `SNI` записывают внешний реальный сайт HTTPS, не записывайте собственное домен панели.

## 3x-ui Быстрая проверка конфигурации трех режимов ввода

Все три режима используют общие домен панели, путь подписки, маршруты сайтов, механизм веб-прокси, локальный TLS-порт и сертификаты. Nginx Stream и TCP Peek также используют общий белый список сайтов. `xray-fallback` его не поддерживает, потому что после fallback локальный веб-прокси Caddy/Nginx не может надёжно определить реальный исходный IP-адрес клиента. Остальные различия сводятся к тому, какая служба слушает публичный порт `443` и должно ли основное входящее подключение 3x-ui/Xray занимать его напрямую.

### Выбор механизма веб-обратный прокси

При первой настройке `[2 Первая настройка/установка Повторное использование порта 443]` вы можете выбрать Caddy или Nginx в качестве локального веб-обратного прокси-сервера под повторным использованием порта 443. Вы также можете следить из:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси] -> [8 переключатель Web механизм обратного прокси]
```

Скрипт будет повторно использовать текущее имя домена, сертификат и бэкенд при переключении; белый список веб-сайтов также будет повторно использоваться в режим входа, поддерживающем белые списки. Скрипт повторно отобразит выбранную конфигурацию механизма и изолирует другой набор из 443 локальных конфигураций обратного веб-прокси, чтобы предотвратить одновременную обработку одной и той же партии из 443 веб-доменов Caddy/Nginx. Пути сертификатов остаются `/etc/caddy/certs/${domain}.crt|key` и `/root/cert/${domain}.crt|key`, а политика сертификатов не меняется.

Если автономный обратный прокси-сервер Caddy/Nginx HTTPS ранее был настроен на `Главное меню [4 обратный прокси]`, то при включении или повторном применении общей записи 443 сценарий изолирует эти старые конфигурации, которые могут захватить Интернет `443`. Пожалуйста, используйте `[19] -> [8 менеджмент Web домен/обратный прокси]`, чтобы добавить новые веб-сайты позже.

### Одинаковые настройки 3x-ui для всех трех режимов.

Эти настройки одинаковы в трех режимах: Nginx Stream, TCP Peek + Splice и Xray Fallback:

| 3x-ui местоположение | Что следует заполнить |
| --- | --- |
| `webListen` | `127.0.0.1` |
| `webPort` | `40000` или фактический порт панели |
| `webBasePath` | `/panel/` или фактический путь панели |
| `webDomain` | Оставьте пустым: публичный домен обслуживает веб-прокси |
| `webCertFile` / `webKeyFile` | Очистить |
| `subListen` | `127.0.0.1` |
| `subPort` | `2096` или фактический порт подписки |
| `subPath` | `/sub/` или фактический путь обычной подписки |
| `subClashPath` | `/clash/` или фактический путь Clash/Mihomo |
| `subDomain` | Публичный домен подписки, например `panel.example.com`; без схемы, порта и пути |
| `subCertFile` / `subKeyFile` | Очистить |

`panel.example.com`, `/sub/` и `/clash/` — примерные значения. Замените их фактическим публичным доменом и путями.

### 3x-ui 3.4.0+ Хосты / Внешний прокси старой версии

В 3x-ui v3.4.0 и новее публичный адрес узла настраивается в `Hosts / Хост`. В старых версиях используется `External Proxy` входящего подключения.

3x-ui v3.4.0 и новее: откройте `Hosts / Хост` и добавьте хост:

```text
Входящее подключение: выберите соответствующее локальное подключение REALITY или Xray
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
Security: то же значение или фактический тип защиты этого входящего подключения
SNI / Fingerprint / ALPN：Поддерживайте фактическое значение входящего и клиентского трафика согласованным
```

3x-ui v3.3.1 и более ранние версии: откройте `External Proxy` в соответствующем входящем REALITY:

```text
Тип: то же значение
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
```

Если панель `External Proxy` была настроена до обновления, вам все равно следует проверить, являются ли адрес и порт в `Hosts / Хост` Интернет-`443` после обновления.

### Режим 1: Nginx Stream

Это стабильный режим по умолчанию. Входящие узлы 3x-ui/Xray не прослушивают публичный порт `443`, а только локальный порт.

| 3x-ui / Xray Настройки входящего подключения | Пример значения |
| --- | --- |
| REALITY или другой локальный адрес прослушивания входящего подключения Xray. | `127.0.0.1` |
| REALITY или другой локальный входящий порт прослушивания Xray | `1443` или ваш фактический локальный входящий порт |
| Адрес подключения клиента | `node.example.com` или IP-адрес сервера в Интернете |
| Порт подключения клиента | `443` |
| REALITY `dest` / `Target` | Внешний реальный сайт HTTPS, например. `www.microsoft.com:443` |
| REALITY `serverNames` / `SNI` | Тот же внешний реальный сайт HTTPS, например. `www.microsoft.com` |
| Hosts / External Proxy | 3x-ui v3.4.0+ добавляет новый хост в `Hosts / Хост`; старая версия установлена ​​во входящем соединении `External Proxy`. Введите адрес `node.example.com` или IP-адрес сервера в Интернете и укажите порт `443`. |

Если вы хотите, чтобы несколько локальных входящих подключений Xray использовали общую сеть `443`, сначала создайте несколько локальных входящих подключений в 3x-ui, каждый входящий использует отдельный `127.0.0.1:порт`, а затем:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [15 Xray управление входящими подключениями]
```

Только запись `SNI -> локальный адрес:порт`, используемая для поддерживаемых в настоящее время правил разгрузки рендеринга в режиме с повторным использованием порта 443. Сценарий не создает, не удаляет и не изменяет входящую внутреннюю конфигурацию 3x-ui/Xray.

### Режим 2: TCP Peek + Splice

В режиме TCP Peek + Splice процесс настройки такой же, как и в Nginx Stream: панель, подписка и входящее подключение Xray по-прежнему прослушивают локальный адрес, а клиент по-прежнему подключается к публичный порт `443`. При переключении на TCP Peek повторно используйте один и тот же набор доменных имен, сертификатов, серверов веб-обратный прокси, веб-белых списков и записей разгрузки Xray SNI.

| Проект | Описание |
| --- | --- |
| 3x-ui Панель и подписка | Оставьте `127.0.0.1` локальным сервером HTTP, путь к сертификату очищен. |
| REALITY или другой входящий Xray | Сохраняйте локальные привязки, такие как `127.0.0.1:1443`. |
| Порт подключения клиента | Еще `443` |
| Hosts / External Proxy | По-прежнему выводится `node.example.com:443` или `Публичная сеть сервера IP:443`. |
| Xray Управление входящими сообщениями | Как и Nginx Stream, поддерживает несколько локальных входящих соединений Xray, маршрутизируемых как SNI. |

При переключении с Nginx Stream на TCP Peek + Splice обычно нет необходимости менять какую-либо конфигурацию в панели 3x-ui. Что изменилось, так это процесс прослушивания публичный порт `443`: с `nginx` на `vpso-mux`.

Преимущества TCP Peek:

1. Процесс настройки аналогичен Nginx Stream, и нет необходимости повторно заполнять 3x-ui, механизм веб-обратный прокси, сертификат или маршрут Xray SNI.
2. `MSG_PEEK` только проверяет ClientHello и не использует первый пакет. бэкенд по-прежнему получает исходное рукопожатие TLS.
3. При пересылке сначала используется сращивание, чтобы уменьшить копирование данных в пользовательском режиме; когда он недоступен, он автоматически возвращается к обычной копии.
4. `vpso-mux` имеет независимый статус, журналы, проверку конфигурации и предварительную проверку 8444 для облегчения подтверждения ссылок до и после переключения.

Проверьте перед переключением:

1. Процесс переключения TCP Peek больше не будет автоматически загружать цепочку инструментов Go или удаленно компилировать `vpso-mux` во время процесса переключения `443` через Интернет.
2. Прежде чем использовать TCP Peek в первый раз, сначала запустите `Главное меню [19] -> [16] Посмотреть TCP Peek + Splice Статус / 8444 Предполетная подготовка`. Этот шаг отслеживает только `8444` и не заменит публичный порт `443`.
3. После прохождения `[16]` запустите `[17] TCP Peek проверка правил маршрутизации` и, наконец, `[5] переключиться на TCP Peek + Splice режим`. Перед переключением скрипт автоматически запустит еще одну независимую предварительную проверку `8444`. В случае неудачи публичный порт `443` использоваться не будет.
4. Если текущий сеанс SSH сам подключен к входному порту Интернета, например `443`, сценарий откажется от переключения. Вместо этого используйте VNC/Serial Console поставщика облака или сначала войдите в систему, используя запретный порт SSH.
5. Перед переключением TCP Peek необходимо соединить локальный порт механизма веб-обратный прокси и локальный входящий порт Xray/REALITY; Если локальные входящие порты, такие как `127.0.0.1:1443`, не отслеживаются, сначала включите соответствующий входящий порт на 3x-ui или измените порт, сохраненный в сценарии, на фактическое значение.

Для первоначальной настройки вам необходимо запустить только тот же набор мастеров `[2 Первая настройка/установка Повторное использование порта 443]`. После подключения общей конфигурации, сертификата, механизма обратного веб-прокси и локального порта 3x-ui выполните описанный выше процесс `[16] -> [17] -> [5]`, чтобы переключить процесс входа в Интернет на TCP Peek.

### Режим 3: Резервный режим Xray

Xray Fallback — это специальный режим. Интернет-`443` привязан к основному входящему соединению 3x-ui/Xray, которое вы настроили, а затем HTTPS подключается в качестве резерва к текущему локальному порту механизма обратного веб-прокси через это основное входящее соединение. Скрипт не будет редактировать внутреннюю конфигурацию входящего соединения 3x-ui/Xray за вас.

Прежде чем перейти на резервный xray, вам необходимо подготовить «основной входящий» в 3x-ui:

| 3x-ui / Xray Основные входящие настройки | Пример значения |
| --- | --- |
| Основной входящий адрес прослушивания | `0.0.0.0`, или метод привязки к Интернету, разрешенный панелью |
| Основной входящий порт прослушивания | `443` |
| резервный вариант/резервный пункт назначения/резервный целевой объект | `127.0.0.1:8443`, порт основан на локальном порте механизма веб-обратный прокси в скрипте. |
| Адрес подключения клиента | `node.example.com` или IP-адрес сервера в Интернете |
| Порт подключения клиента | `443` |
| Hosts / External Proxy | Если ссылка на подписку не выводит `:443`, в `Hosts / Хост` устанавливается 3x-ui v3.4.0+; устаревшие версии устанавливаются во входящем соединении `External Proxy`. Введите домен узла или IP-адрес сервера в качестве адреса и введите `443` в качестве порта. |

Веб-панель и подписки по-прежнему используют текущий механизм веб-обратный прокси, поэтому путь к сертификату панели и путь к сертификату подписки по-прежнему необходимо очистить. Ссылка доступа `panel.example.com` должна быть:

```text
Браузер -> Публичная сеть 443 -> Xray основное входящее подключение fallback -> Web механизм обратного прокси 127.0.0.1:8443 -> 3x-ui Панель/Подписка
```

Резервный режим xray не поддерживает сценарии, которые продолжают разгружать несколько SNI на несколько локальных входящих Xray. В меню `Xray управление входящими подключениями` можно просматривать только существующие правила и текущих основных входящих кандидатов, но нельзя добавлять, удалять или синхронизировать правила. Если требуется несколько локальных входящих вызовов Xray, используйте Nginx Stream или TCP Peek + Splice.

Если вашим основным входящим соединением является REALITY, убедитесь, что тип входящего соединения 3x-ui/Xray, который вы используете, действительно может быть резервным HTTPS для текущего механизма обратного веб-прокси. Этот сценарий только проверяет, связан ли `443` с Xray в Интернете и доступен ли резервный сервер обратного прокси-сервера Web. Он не будет генерировать для вас резервные правила Xray.

### При переключении режимов нужно ли менять 3x-ui?

| Переключение направления | 3x-ui Что нужно сделать? |
| --- | --- |
| Nginx Stream -> TCP Peek + Splice | Обычно нет необходимости менять 3x-ui. Оставьте Panel/Subscription/Xray, чтобы прослушивать локальный адрес для входящих вызовов, а порт клиента по-прежнему будет `443`. |
| TCP Peek + Splice -> Nginx Stream | Обычно нет необходимости менять 3x-ui. После переключения обратно публичный порт `443` контролируется Nginx stream. |
| Nginx Stream или TCP Peek + Splice -> Xray Резервный вариант | Сначала измените основной входящее подключение в 3x-ui на публичный порт `443`, настройте резервный порт на локальный порт механизма веб-обратный прокси, а затем выполните переключение сценария. |
| Резервный вариант Xray -> Nginx Stream или TCP Peek + Splice | Сначала переместите основное входящее соединение 3x-ui/Xray из Интернета `443`, измените его обратно на локальный порт, например `127.0.0.1:1443`, или сначала отключите основное входящее соединение публичного порта 443, а затем выполните переключение сценария. |
| Повторно применить текущий шаблон | Если вы просто пересобираете конфигурацию, то 3x-ui менять не нужно; Если вы изменили порт панели, путь подписки или локальный порт Xray, сначала сохраните значение в сценарии синхронизации `[10 Изменить параметры повторного использования порта 443]`. |

Прежде чем вернуться к Nginx Stream или TCP Peek + Splice с резервного xray, самая распространенная ошибка — забыть переместить основное входящее соединение 3x-ui/Xray из Интернета `443`. В противном случае Nginx или `vpso-mux` захватит тот же публичный порт, что и Xray, и коммутатор выйдет из строя или автоматически откатится назад.

ss -lntp | grep ':443'
```

Проверка переключения TCP Peek + Splice:

Главное меню [19 Управление повторным использованием порта 443] -> [17 TCP Peek проверка правил маршрутизации]
Главное меню [19 Управление повторным использованием порта 443] -> [5 переключиться на TCP Peek + Splice режим]
```

Только после прохождения предварительной проверки `8444` и проверки правила перенаправления `[5] переключиться на TCP Peek + Splice режим` может быть выполнен. Чтобы отменить последний переключатель режима входа, используйте `Главное меню [19 Управление повторным использованием порта 443] -> [7 Откатить последнее переключение режима входа]`.

Проверка после переключения:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]
Главное меню [19 Управление повторным использованием порта 443] -> [14 443 Тест доступа к сети]
```

Ожидаемые слушатели:

| ENTRY_MODE | Кто должен следить за публичной сетью 443? |
| --- | --- |
| `nginx-stream` | `nginx` |
| `tcp-peek` | `vpso-mux` |
| `xray-fallback` | `xray` / `3x-ui` / `x-ui` Размещенный Xray |

Новое значение конфигурации `ENTRY_MODE` записывается только в `nginx-stream`, `xray-fallback` и `tcp-peek`. Если в старой конфигурации нет `ENTRY_MODE`, скрипт читается как `nginx-stream`; если в старой конфигурации есть `nginx_stream`, `xray_fallback` и `tcp_peek` или `/etc/vps-optimize/443-engine.conf`, скрипт считает соответствующие новые значения совместимыми. Одно простое назначение будет автоматически перезаписано под новым именем; если его невозможно безопасно переписать, страница состояния будет продолжать предлагать выполнить миграцию.

Независимо от режима, не предоставляйте механизм обратного веб-прокси, порт панели 3x-ui, порт подписки или дополнительные локальные входящие подключения непосредственно к Интернету.

## Xray Граница входящего управления

`Xray управление входящими подключениями` записывает только маршрутизирующие записи `SNI -> локальный адрес:порт` для поддерживаемых в настоящее время правил маршрутизирования рендеринга в режиме с повторным использованием порта 443, он не является входящим редактором 3x-ui/Xray. Пользователям необходимо сначала создать и включить локальное входящее подключение в 3x-ui/Xray, а затем записать в скрипт соответствующий SNI, локальный адрес прослушивания и порт.

Режим TCP Peek + Splice: чтение SNI в TLS ClientHello на основе MSG_PEEK, без использования первого пакета, и маршрутизирование соединения с механизмом веб-обратный прокси или локальным сервером Xray на основе SNI; При пересылке предпочтительнее использовать нулевую копию сращивания, а обычная копия автоматически откатывается в случае сбоя. Действующая программа маршрутизирования — vpso-mux.

Режимы Nginx Stream и TCP Peek + Splice поддерживают перенаправление нескольких SNI на несколько локальных входящих соединений Xray на основе одного и того же правила маршрутизации входящих соединений Xray. Имена веб-доменов по-прежнему перенаправляются в текущий механизм обратного веб-прокси, а на входящие соединения Xray не влияет белый список веб-сайтов.

Сам Xray может иметь несколько входящих подключений. Однако в резервном режиме xray публичный порт `443` по умолчанию перехватывается входящим главным устройством Xray. В настоящее время сценарий не поддерживает продолжение перенаправления нескольких SNI на несколько локальных входящих Xray в этом режиме. Для нескольких локальных входящих разгрузок Xray используйте режим Nginx Stream или режим TCP Peek + Splice.

После перехода на xray-fallback скрипт сохранит существующие правила в `/etc/vps-optimize/xray-sni-routes.conf` и не удалит их. Выбранное правило используется как основной входящий резервный вариант xray; другие правила будут помечены как «зарезервированы, но не эффективны в текущем резервном режиме xray». При последующем переключении обратно в режим Nginx Stream или TCP Peek + Splice эти правила могут быть повторно использованы для разгрузки SNI.

В режиме xray-fallback меню `Управление входящими подключениями Xray` позволяет просматривать правила и текущее основное входящее подключение, но не позволяет добавлять, удалять или синхронизировать правила. Это меню не изменяет параметры входящих подключений 3x-ui/Xray; отдельная защита трафика REALITY fallback может изменять только два поля ограничения скорости, описанные ниже.

## Разница между обычным TLS и REALITY

Обычные узлы TLS уделяют больше внимания тому, совпадают ли локальный сертификат, резервный веб-сервер и хост/SNI. Например, для таких узлов, как VLESS + TLS, Trojan + TLS, VMess + WS + TLS, VLESS + gRPC + TLS, при устранении неполадок следует подтвердить, контролируется ли домен узла пользователем, распространяется ли локальный сертификат на SNI, работает ли механизм веб-обратный прокси. имеет соответствующий резервный вариант и возвращает ли доступ браузера 200/301/302.

Узлы REALITY разные. REALITY уделяет больше внимания тому, действительно ли внешний целевой сайт доступен, стабильны ли характеристики TLS и являются ли `serverName` и `dest` логически согласованными. Не требуется REALITY `serverName` для присоединения к механизму веб-обратный прокси, а также не требуются собственные сертификаты для покрытия REALITY `serverName`.

## Защита трафика REALITY fallback

REALITY пересылает подключения с ошибкой проверки на `target`. Для запуска этого fallback-пути сканеру не нужны UUID, shortId или ключ. Если `target` находится за CDN, сервер может использоваться как ретранслятор и расходовать трафик.

Откройте `Главное меню [19 Управление повторным использованием порта 443] -> [17 Защита трафика REALITY fallback]`. Доступны два уровня защиты:

- Строгий контроль SNI: работает в режимах Nginx Stream и TCP Peek. Разрешает только зарегистрированный домен панели, домены сайтов, маршруты TCP/Xray SNI и REALITY SNI; неизвестные подключения и подключения без SNI отклоняются. Отдельный список разрешений не хранится: он формируется из текущей конфигурации при каждой генерации входа. После добавления, удаления или изменения домена либо маршрута выполните его синхронизацию или повторно примените текущий вход.
- Ограничение скорости REALITY fallback: работает с SQLite 3x-ui. Сначала создаётся резервная копия базы, затем в выбранном входящем REALITY изменяются только `limitFallbackUpload` и `limitFallbackDownload`; значения при каждой настройке генерируются случайно. UUID, shortId, ключи, протокол, транспорт и остальные поля входящего подключения не меняются. PostgreSQL автоматически не изменяется.

В режиме `xray-fallback` Xray напрямую слушает публичный порт 443, поэтому отдельного входного контроля SNI нет; доступно только ограничение скорости fallback. Ограничение скорости само создаёт отличительный признак. Предпочтительнее выбирать REALITY-цель без CDN и с подходящим для сервера сетевым расположением, а ограничение включать только при неизбежном использовании CDN.

## Политика сертификатов

Port 443 Reuse продолжает использовать `acme.sh + Cloudflare DNS API` для выдачи и установки сертификатов имен веб-доменов. Не используйте модуль Caddy DNS, не требуйте `xcaddy` и не позволяйте Caddy отвечать за приложение сертификата DNS-01.

DNS-01 Проверяет управление доменным именем посредством записи TXT `_acme-challenge`. Cloudflare Chengyun сам по себе не является непосредственной причиной сбоя выдачи `dns_cf`; Если выдача не удалась, вам следует сначала проверить разрешения токена, зону авторизации, распространение TXT, время сервера и журналы acme.sh. Orange Cloud по-прежнему будет менять исходный IP-адрес веб-запросов и не подходит для доменных имен REALITY/узла, которые необходимо напрямую подключать к VPS, поэтому «выдача сертификата» и «Ссылка для доступа в Интернет» должны быть проверены отдельно.

Выбор сертификата, который появляется на этапе установки 3x-ui, предназначен только для завершения процесса установки 3x-ui; это не та схема сертификатов, которая в конечном итоге используется повторным использованием порта 443. Окончательная архитектура такова: Интернет HTTPS единообразно обрабатывается текущим механизмом обратного веб-прокси, а панели и подписки 3x-ui служат только локальными серверными модулями HTTP.

## Белый список IP-адресов доменных имен

Если вам нужен только фиксированный IP-адрес для доступа к доменному имени панели 3x-ui, вы можете включить белый список IP-адресов для указанного имени веб-домена. Это ограничение вступает в силу «по имени домена»: добавление белого списка к `panel.example.com` ограничит только это имя веб-домена; доменные имена сайтов, не внесенные в белый список, входящие Xray, REALITY, SNI и неизвестные SNI будут продолжать работать в соответствии с исходными правилами маршрутизация 443.

Реализация двух методов развертывания различна:

| Метод развертывания | Используйте вход | Эффективная позиция | Сфера влияния |
| --- | --- | --- | --- |
| Повторное использование порта 443 не включен, используется только обратный прокси Caddy/Nginx. | Используйте `Главное меню [4 обратный прокси] -> [1 добавить Caddy обратный прокси]` или `[2 добавить Nginx HTTPS обратный прокси]` при добавлении нового доменного имени; используйте `[4] -> [5 домен IP белый список]` для существующих доменных имен; используйте `[4] -> [6 Просмотреть или изменить применённые файлы конфигурации]` для прямого редактирования и настройки. | Caddy Текущий блок сайта с доменным именем использует для сопоставления `remote_ip`; Nginx HTTPS использует `allow/deny` для обратный прокси. | Влияет только на текущее имя веб-домена Caddy/Nginx. |
| Включено 443 Nginx Stream, один вход | `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси] -> [5 Управление доменными именами IP белый список]` | Входной слой Nginx stream, эксперт `SNI + источник IP` | Влияет только на выбранное домен SNI. |
| Включено 443 TCP Peek + Splice, один вход | `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси] -> [5 Управление доменными именами IP белый список]` | Входной слой vpso-mux, эксперт `SNI + источник IP` | Влияет только на выбранное домен SNI. |
| `xray-fallback`, независимо от выбора Caddy или Nginx | Нельзя создавать, сохранять или применять белый список сайтов | После fallback Xray локальный веб-прокси не может надёжно определить реальный исходный IP-адрес клиента | Для белого списка переключитесь на Nginx Stream или TCP Peek |

Белый список поддерживает отдельные IP-адреса и CIDR, например:

```text
1.2.3.4
1.2.3.0/24
2001:db8::/32
```

Пожалуйста, поместите текущий IP-адрес управления в белый список перед его включением, иначе вы можете заблокировать себя на панели. Скрипт запросит текущий исходный IP-адрес SSH и автоматически попытается добавить локальный Интернет VPS IPv4/IPv6, адрес обратной связи и текущую подсеть сети Docker в белый список; Если автоматическое обнаружение не удалось, вручную добавьте IP-адрес VPS в Интернете или подсеть Docker, где расположен инструмент подписки.

Примечание. В этом плане рекомендуется сохранять соответствующие доменные имена только как Cloudflare Grey Cloud / DNS. Если для доменного имени включен прокси-сервер Orange Cloud, исходный IP-адрес, видимый сервером, может быть граничным IP-адресом Cloudflare, а не вашим реальным IP-адресом доступа. Белый список следует изменить на граничный сегмент Cloudflare или сначала отключить прокси.

## Подготовка

Подготовьте хотя бы одно домен панели:

```text
panel.example.com -> текущий VPS IP
```

Рекомендуется подготовить домен другого узла:

```text
node.example.com -> текущий VPS IP
```

Cloudflare Предложения:

| домен | Предложения |
| --- | --- |
| домен панели | Серое облако / только DNS |
| домен узла | Только Huiyun / DNS, должна быть возможность прямого подключения к VPS. |
| Веб-сайт или обратное домен | Серое облако / только DNS |
| Маскировка REALITY SNI | Напишите внешний реальный сайт HTTPS, не указывайте на свой VPS. |

Не рекомендуется включать прокси-сервер Cloudflare для доменных имен, связанных с этим планом. Прямое соединение Grey Cloud больше подходит для перенаправления Nginx stream на SNI, а также может уменьшить количество исключений в REALITY, ссылках подписки и хостах/внешних прокси.

Для маскировочного SNI REALITY выбирайте стабильный внешний HTTPS-сайт без CDN, доступный из сетей ваших пользователей. Не используйте домен панели, узла или подписки, а также сайты с частыми перенаправлениями, блокировкой нестандартных запросов или CAPTCHA. В текущих версиях 3x-ui пустой `Min Client Ver` использует встроенную минимальную версию Xray core, а не разрешает все версии; сначала обновите core проблемного стороннего клиента и рассматривайте `1.0.0` только при принятом риске устаревших отпечатков.

Если вы используете Cloudflare DNS для подписи сертификата, токену API потребуется как минимум:

```text
Zone.Zone.Read
Zone.DNS.Edit
```

## Рекомендуемый процесс развертывания

Чтобы избежать головокружения, следуйте следующему порядку:

```text
1. Подготовьте домен и Cloudflare Token
2. Установка 3x-ui
3. Используйте 3x-ui как локальный HTTP-бэкенд
4. Настройте входящее подключение REALITY
5. Откройте `Главное меню [19 Управление повторным использованием порта 443] -> [2 Первая настройка/установка повторное использование порта 443]`
6. Вернитесь в 3x-ui и проверьте локальные привязки, поля подписки и Hosts / External Proxy
7. Откройте `Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]`
```

### 1. Установите 3x-ui.

Когда текущий установщик 3x-ui спросит о настройке SSL, выберите пункт 4: `Skip SSL (advanced — behind reverse proxy / SSH tunnel only)`, затем введите `y` для привязки только к `127.0.0.1`. Используйте этот режим только за обратным прокси или SSH-туннелем; не открывайте незашифрованную HTTP-панель в Интернет. В 2.x или существующей установке с SSL очистите пути сертификатов панели и подписки до перехода на 443.

| Опции установщика | Роль в этом уроке | Последующая обработка |
|---|---|---|
| Skip SSL | Рекомендуемый локальный HTTP-бэкенд | Привязать только к `127.0.0.1` |
| Подать заявку на сертификат на домен | Может использоваться для временного завершения установки 3x-ui. | Очистите путь сертификата 3x-ui перед доступом к 443. |
| Запросить сертификат на IP | Только как временный переход, не рекомендуется как формальный Интернет HTTPS | Очистите путь сертификата 3x-ui перед доступом к 443. |
| Выберите существующий путь сертификата | Может использоваться для временного завершения установки. | Очистите путь сертификата 3x-ui перед доступом к 443. |

Пример:

```text
домен сертификата：panel.example.com
Устанавливать ли его на панель：Вы можете выбрать быть
```

Приведенные выше значения являются лишь примерами. Замените их реальными доменными именами. Когда позже будет официально получен доступ к повторном использовании порта 443, путь сертификата 3x-ui необходимо очистить, и механизм обратного веб-прокси сможет взять на себя управление Интернетом HTTPS.

Рекомендуется настроить эти значения и записать их:

```text
Порт панели：40000
панель url корневой путь：/panel/
Имя пользователя/пароль：Установите это сами
прослушивание IP：127.0.0.1
SSL：Skip SSL / Не применять SSL
```

Собственный адрес проверки бэкенда:

```text
http://127.0.0.1:40000/panel/
```

Если ваш порт или путь отличаются, замените их собственным значением. Путь панели рекомендуется использовать с передним и задним `/`.

### 2. Очистите сертификат панели 3x-ui.

Если вы готовы получить доступ к повторному использованию порта 443 в VPS-Optimize, вам следует очистить панель 3x-ui и путь к сертификату подписки, чтобы позволить механизму обратного веб-прокси взять на себя управление Интернетом HTTPS.

Введите:

```text
Поля `webCertFile` и `webKeyFile` в настройках панели
```

Очистите все следующие пути:

```text
Путь к сертификату
Путь к закрытому ключу
Путь к файлу открытого ключа
Путь к файлу закрытого ключа
```

Сохраните и перезапустите панель.

Если этот параметр не очищен, это может привести к ошибке 502 Bad Gateway, несоответствию внутреннего протокола HTTP/HTTPS, петле перенаправления, путанице пути сертификата, исключению панели или подписки.

После очистки панель 3x-ui будет служить только собственным бэкэндом HTTP:

```text
http://127.0.0.1:40000/panel/
```

Публичная сеть имеет доступ только к стандартному адресу HTTPS: `https://panel.example.com/panel/`.

### 3. Очистить сертификат подписки 3x-ui.

Введите:

```text
Поля `subCertFile` и `subKeyFile` в настройках подписки
```

Также очистите путь к сертификату и путь к закрытому ключу. После доступа к повторному использованию порта 443 интернет-подписка HTTPS также единообразно обрабатывается текущим механизмом обратного веб-прокси, а служба подписки 3x-ui служит только локальным бэкэндом HTTP.

Затем настройте службу подписки:

```text
subListen：127.0.0.1
subDomain：panel.example.com
subPort：2096
subPath：/sub/
subClashPath：/clash/
```

В `subDomain` указывается только домен без схемы, порта и пути. 3x-ui не добавляет `/` к путям подписки автоматически. Укажите:

```text
/sub/
/clash/
/mihomo/
```

Не пишите:

```text
sub
/sub
sub/
/sub/ПОДПИСКА_КЛИЕНТА
```

443 Мастер заполняет префикс пути, например `/sub/`, `/clash/`. Не заполняйте имя домена и не заполняйте `Subscription` клиента под сайтом.

### 4. Настройте входящее подключение REALITY.

Добавьте входящий VLESS REALITY по адресу 3x-ui:

```text
соглашение：VLESS
адрес прослушивания：127.0.0.1
порт прослушивания：1443
передача：TCP / RAW
Security：Reality
uTLS：chrome
Target / dest：внешняя реальность HTTPS сайт:443, Например www.microsoft.com:443
serverNames / SNI：та же внешняя реальность HTTPS сайт, Например www.microsoft.com
SpiderX：/
Fallbacks：Оставьте пустым
```

Не записывайте `dest` или `serverNames` в REALITY как:

```text
panel.example.com:443
node.example.com:443
127.0.0.1:8443
```

Чтобы изменить REALITY SNI позже, вы можете сделать:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [10 Изменить параметры повторного использования порта 443] -> [2 Изменить REALITY локальный слушатель / маскировка SNI]
```

### 5. Запустите 443 первую конфигурацию.

Убедившись, что сертификат панели и сертификат подписки очищены, запустите:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [2 Первая настройка/установка повторное использование порта 443]
```

Пример заполнения:

| Проект | Пример значения |
| --- | --- |
| домен панели | `panel.example.com` |
| Веб-сайт/обратное домен | Первое время можно оставить пустым. |
| Маскировка REALITY SNI | `www.microsoft.com` или другой внешний реальный сайт HTTPS |
| Nginx Адрес привязки к Интернету | `0.0.0.0` |
| Nginx Порт привязки к Интернету | `443` |
| Механизм веб-обратный прокси | `Caddy` или `Nginx` |
| Локальный адрес прослушивания механизма веб-обратный прокси | `127.0.0.1` |
| Локальный порт прослушивания механизма веб-обратный прокси | `8443` |
| Xray REALITY локальный адрес прослушивания | `127.0.0.1` |
| Xray REALITY локальный порт прослушивания | `1443` |
| Адрес привязки панели 3x-ui | `127.0.0.1` |
| Порт панели 3x-ui | `40000` |
| Интернет-путь панели 3x-ui | `/panel/` |
| Адрес прослушивания подписки 3x-ui | `127.0.0.1` |
| Порт подписки 3x-ui | `2096` |
| Префикс общего пути подписки | `/sub/` |
| Префикс пути Clash/Mihomo | `/clash/` |
| Cloudflare API Token | Ваш токен CF |

Путь к панели, обычный путь подписки и путь Clash/Mihomo должны быть точно такими же, как у 3x-ui.

Каждый раз, когда сценарий настраивается в первый раз, применяется повторно, переключает механизмы веб-обратный прокси, добавляет или удаляет веб-сайты, он сначала создает резервную копию стека SNI. Если `nginx -t`, `caddy validate` или службе не удастся перезапуститься, она попытается выполнить откат и переместить ненормальную конфигурацию в каталог изоляции.

Общие каталоги резервного копирования и карантина:

```text
/etc/vps-optimize/backups/sni-stack_*
/etc/vps-optimize/quarantine/nginx-sni
/etc/vps-optimize/quarantine/nginx-sni-web
/etc/vps-optimize/quarantine/nginx-proxy-to-443-entry
/etc/vps-optimize/quarantine/caddy-sni
/etc/vps-optimize/quarantine/caddy-sni-web
/etc/vps-optimize/quarantine/caddy-certs
```

### 6. Вернитесь к 3x-ui, чтобы закончить.

Убедитесь, что 3x-ui по-прежнему является собственным бэкэндом HTTP:

```text
слушатель панели IP：127.0.0.1
слушатель подписки IP：127.0.0.1
```

Проверьте текущие поля подписки:

```text
subDomain：panel.example.com
subPath：/sub/
subClashPath：/clash/
```

В `subDomain` не указывайте схему, порт или путь; при собственных путях обновите соответствующие префиксы, сохранённые сценарием.

Затем установите интернет-адрес узла в соответствии с версией 3x-ui.

3x-ui v3.4.0 и новее: откройте `Hosts / Хост` и добавьте хост:

```text
Входящее подключение: выберите соответствующее локальное подключение REALITY или Xray
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
Security: то же значение или фактический тип защиты этого входящего подключения
SNI / Fingerprint / ALPN：Поддерживайте фактическое значение входящего и клиентского трафика согласованным
```

3x-ui v3.3.1 и более ранние версии: откройте `External Proxy` во входящем REALITY:

```text
Тип: то же значение
Адрес: node.example.com или публичный IP-адрес сервера
Порт: 443
```

После сохранения скопируйте ссылку на узел еще раз. Порт должен быть `:443`. Если это все еще `:1443`, проверьте `Hosts / Хост` для 3x-ui v3.4.0+ и проверьте `External Proxy` для более старых версий.

Наконец запустите:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]
```

## Последующее техническое обслуживание

Не повторяйте первую конфигурацию только для небольших изменений. Обычно используемые входы следующие:

| что ты хочешь сделать | вход |
| --- | --- |
| Добавить новый веб-сайт или изменить домен | `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]` |
| Коммутатор Caddy/Nginx Механизм веб-обратный прокси | `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси] -> [8 переключатель Web механизм обратного прокси]` |
| Проверьте ссылку 443 | `Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]` |
| Изменить порт и путь панели/подписки | `Главное меню [19 Управление повторным использованием порта 443] -> [10 Изменить параметры повторного использования порта 443] -> [1 Изменить порты и пути панели/подписки]` |
| Изменить локальную привязку/маскировку REALITY SNI | `Главное меню [19 Управление повторным использованием порта 443] -> [10 Изменить параметры повторного использования порта 443] -> [2 Изменить REALITY локальный слушатель / маскировка SNI]` |
| Измените привязку обратного прокси-сервера Nginx/Web. | `Главное меню [19 Управление повторным использованием порта 443] -> [10 Изменить параметры повторного использования порта 443] -> [3 Изменить Nginx Интернет-точка входа / Web обратный прокси локальный TLS]` |
| Изменить домен панели | `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси] -> [9 Изменить домен панели]` |
| Повторно применить текущую конфигурацию | `Главное меню [19 Управление повторным использованием порта 443] -> [10 Изменить параметры повторного использования порта 443] -> [5 Повторно применить сохранённую конфигурацию]` |
| Обслуживание сертификатов | `Главное меню [19 Управление повторным использованием порта 443] -> [12 CF DNS / Caddy Обслуживание сертификатов]` |
| Откат 443 конфигурации с повторным использованием порта 443 | Запись отката в `Главное меню [19 Управление повторным использованием порта 443] -> [12 CF DNS / Caddy Обслуживание сертификатов]` |

При добавлении нового сайта/обратный прокси заполните бэкенд, доступный текущему VPS. Служба Docker может сначала опубликовать порт контейнера в `127.0.0.1`:

```text
домен сайта：dockge.example.com
Внутренний адрес：127.0.0.1
внутренний порт：5001
```

`127.0.0.1:5001` — это пример значения. Замените Docker адресом и портом, фактически опубликованными на хосте. Службы интрасети также могут использовать фактический IP-адрес или имя хоста интрасети, но сначала вы должны убедиться, что к текущему VPS возможен прямой доступ.

Затем браузер обращается к:

```text
https://dockge.example.com/
```

К сервисам, подходящим для интеграции, относятся SublinkPro, Sub-Store, Dockge, Komari, блоги и другие собственные сервисы HTTP.

## Отладочная запись

При недоступности панели, ошибке 404 подписки, сбое сертификата, занятом порте или проблеме с REALITY откройте [Диагностика повторного использования порта 443](443-single-entry-troubleshooting.md).

## Полный набор примеров только для справки.

```text
Панель: https://panel.example.com/panel/
Обычная подписка: https://panel.example.com/sub/ПОДПИСКА_КЛИЕНТА
Clash/Mihomo: https://panel.example.com/clash/ПОДПИСКА_КЛИЕНТА
Узел REALITY: node.example.com:443

Панель 3x-ui: 127.0.0.1:40000
Служба подписки 3x-ui: 127.0.0.1:2096
Входящее подключение REALITY: 127.0.0.1:1443
Веб-прокси: 127.0.0.1:8443 (пример; фактическое значение берётся из текущей конфигурации скрипта)
Публичный порт 443: служба текущего ENTRY_MODE (nginx-stream=nginx; xray-fallback=основное входящее подключение Xray; tcp-peek=vpso-mux)
```

## Никогда не делайте следующее

```text
Публиковать https://panel.example.com:40000/
Публиковать https://panel.example.com:2096/sub/xxxx
Указывать panel.example.com:443 в REALITY dest
Указывать домен панели в REALITY serverNames
Запускать маршрутизацию порта 443, не очистив пути сертификата в 3x-ui
Указывать путь URI подписки как sub или /sub
Вводить ПОДПИСКА_КЛИЕНТА вместо префикса пути в мастере настройки 443
Разрешать веб-прокси, Xray и панели 3x-ui одновременно занимать публичный порт 443
```
