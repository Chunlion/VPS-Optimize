# Перенос существующего сервера на повторное использование порта 443

Этот документ предназначен для VPS, на которых уже есть службы: у них уже есть веб-сайты 3x-ui, Caddy/Nginx, инструменты подписки и проекты Docker Compose. Они хотят передать публичную сеть `443` повторному использованию порта 443 VPS-Optimize.

Основные принципы: сначала инвентаризация, затем резервное копирование, затем миграция. Не запускайте первую конфигурацию, не зная, какой порт прослушивает старая служба, где находится старая конфигурация и как был выдан старый сертификат.

Путь к меню в этой статье записан в формате «главное меню [копия номера меню] -> [копия меню подномера]».

## Подходит для кого

| текущая ситуация | Подходит ли это? |
|---|---|
| У вас уже есть 3x-ui, и вы хотите использовать Интернет для панели и подписки `443`. | подходит для |
| У вас уже есть веб-сайт Caddy, и вы хотите поделиться `443` с 3x-ui / REALITY. | подходит для |
| Уже занят Nginx/Apache `443` | Подходит, но старый сайт должен быть задокументирован перед миграцией |
| У вас уже есть инструмент подписки Docker, и вы хотите добавить домен HTTPS. | подходит для |
| Я не знаю, какие службы работают на машине. | Сначала проведите инвентаризацию, не переносите напрямую |

## Подготовка к миграции

| Подготовительные предметы | Описание |
|---|---|
| Снимок VPS | Необходимо сделать перед миграцией |
| Текущая сессия SSH | Оставайтесь непрерывными на протяжении всего процесса |
| Группа безопасности поставщиков облачных услуг | Выпущены порты SSH и `443/tcp`. |
| Список доменных имен | домен панели, домен подписки, домен веб-сайта, домен узла |
| серверный манифест | Локальный адрес прослушивания и порт для каждой службы |
| Cloudflare Token | Используется для выдачи сертификатов для DNS. |
| Резервная копия старой конфигурации | Caddy/Nginx/panel/Docker Compose необходимо создать резервную копию. |

## Шаг первый: оцените текущую ситуацию

Первый запуск:

```text
Главное меню [1 Предварительная проверка и анализ рисков]
Главное меню [15 Обзор состояния служб]
```

Снова запишите вручную:

```bash
ss -lntp
systemctl status caddy nginx apache2 httpd x-ui docker --no-pager
docker ps
```

Заполните таблицу ниже. Имя домена и порт в таблице являются примерными значениями; при миграции замените их фактическим доменным именем, внутренним адресом и портом.

| домен/услуга | Текущий доступ в Интернет | Внутренний адрес | внутренний порт | Местоположение конфигурации | Вы хотите мигрировать |
|---|---|---|---|---|---|
| `panel.example.com` | `:40000` или `:443` | `127.0.0.1` | `40000` | Панель 3x-ui | Да |
| `sub.example.com` | `:3000` или `:443` | `127.0.0.1` | `3000` | Docker / Caddy | Зависит от ситуации |
| `site.example.com` | `:443` | `127.0.0.1` | `8080` | Caddy/Nginx | Да |

Сосредоточьтесь на поиске тех, кто занимает публичный порт `443`:

```bash
ss -lntp | grep ':443'
grep -R "listen.*443" /etc/nginx /etc/caddy 2>/dev/null
```

## Шаг 2. Создайте резервную копию

Сначала создайте полную резервную копию скрипта:

```text
Главное меню [16 Резервное копирование и откат конфигурации] -> [1 Создать полную резервную копию конфигурации]
```

Подтвердите список резервных копий еще раз:

```text
Главное меню [16 Резервное копирование и откат конфигурации] -> [2 Просмотреть существующие резервные копии]
```

Если конфигурация Caddy/Nginx уже существует, дополнительно запишите эти каталоги:

```text
/etc/caddy/Caddyfile
/etc/caddy/conf.d
/etc/caddy/certs
/etc/nginx/nginx.conf
/etc/nginx/conf.d
/etc/nginx/sites-enabled
/etc/nginx/stream.d
```

Если проект Docker Compose уже существует, запишите:

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
find /opt -maxdepth 3 -name 'docker-compose.yml' -o -name 'compose.yml' 2>/dev/null
```

## Шаг третий: выберите маршрут миграции

| Текущий статус | Рекомендуемый маршрут |
|---|---|
| Только 3x-ui, других сайтов нет. | Для развертывания нажмите непосредственно 3x-ui + 443. |
| Уже есть 3x-ui и поставляется с HTTPS. | Сначала очистите путь сертификата 3x-ui, а затем получите доступ к 443. |
| Уже есть обратный прокси-сервер Caddy. | Запишите старое домен и бэкенд и добавьте их по одному после включения 443; вы можете продолжать выбирать Caddy или переключиться на обратный локальный веб-прокси Nginx. |
| Веб-сайт Nginx/Apache уже существует. | Сначала измените бэкенд веб-сайта на локальный порт, а затем используйте имя веб-домена/обратный прокси-сервер повторного использования порта 443 для добавления; вы можете выбрать локальный обратный веб-прокси Caddy или Nginx. |
| Контейнер инструмента подписки Docker уже существует, но повторное использование порта 443 ещё не включён. | Сохраните контейнер и через `Главное меню [4 Обратный прокси]` выберите Caddy или Nginx HTTPS. |
| Уже есть инструмент подписки Docker, готовый включить повторное использование порта 443. | Сохраните контейнер и измените внешний доступ на одновходное имя веб-домена 443/обратный прокси. |

Полное описание 3x-ui + REALITY + 443 шагов см. в [../tutorials/01-3x-ui-reality-443.md](../tutorials/01-3x-ui-reality-443.md).

Информацию о миграции сервисов подписок см. в разделе [Сервисы подписок на порту 443](../tutorials/02-subscription-tools-caddy-nginx-reverse-proxy-443-single-entry.md).

## HTTPS обратный переход прокси-сервера, когда повторное использование порта 443 не включен

Если вы на данный момент не готовы включить повторное использование порта 443, а просто хотите сначала добавить домен HTTPS в инструмент подписки или на веб-сайт, вы можете использовать независимый точка входа обратного прокси:

```text
Главное меню [4 обратный прокси]
```

Дополнительный процесс:

| вход | Подходит для ситуации |
|---|---|
| `[1 добавить Caddy обратный прокси]` | Уже используете Caddy или хотите, чтобы обратный прокси-сервер этого доменного имени управлялся Caddy. |
| `[2 добавить Nginx HTTPS обратный прокси]` | Повторное использование порта 443 не включен, и есть надежда, что Nginx будет напрямую подключен к Интернету 80/443. |

Nginx HTTPS будет повторно использовать существующий процесс сертификата `acme.sh + Cloudflare DNS API`, и сертификат по-прежнему будет установлен в `/etc/caddy/certs/${domain}.crt|key` и программно связан с `/root/cert/`. `${domain}` является заполнителем и при использовании будет заменен вашим настоящим доменным именем.

Что следует отметить:

1. Этот процесс подходит только для серверов, где повторное использование порта 443 ещё не включён.
2. Если включена повторное использование порта 443, обратный прокси Nginx HTTPS захватит публичный порт `443`. Вместо этого вам следует использовать `Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]` и выбрать в этом меню механизм локальной веб-обратный прокси Caddy или Nginx.
3. Одно и то же домен может управляться только одним из точка входаов Caddy или Nginx. Не настраивайте его повторно.
4. Бэкэнду по-прежнему рекомендуется слушать `127.0.0.1:порт`, например `127.0.0.1:3000`. Имя домена и порт являются примерными значениями. Замените их фактическими значениями.

## Перенести существующий 3x-ui

### целевое состояние

Следующие `40000`, `2096` и `1443` являются примерами портов; фактическая конфигурация зависит от 3x-ui, Xray и конфигурации, сохраненной в сценарии.

| Проект | цель |
|---|---|
| Обвязка панели | `127.0.0.1:40000` |
| Панель HTTPS | Закрыть, путь к сертификату очищен |
| Путь панели | Например `/panel/` |
| Подпишитесь, чтобы слушать | `127.0.0.1:2096` |
| Путь подписки | Например `/sub/`, `/clash/` |
| Привязка REALITY | `127.0.0.1:1443` |
| Порт клиентского узла | `443` |

### Операционный вход

Введите 3x-ui:

```text
Главное меню [5 панель、Узлы и инструменты подписки] -> [1 3x-ui скрипт панели]
```

Если сертификат панели или путь испорчены, сначала воспользуйтесь кирпичным спасательным входом:

```text
Главное меню [5 панель、Узлы и инструменты подписки] -> [3 панель SSL Ремонт]
```

Получите доступ к 443 снова в первый раз:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [2 Первая настройка/установка повторное использование порта 443]
```

Физикальное обследование после бега:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]
```

### Проверить

```bash
curl -I http://127.0.0.1:40000/panel/
curl -I http://127.0.0.1:2096/sub/
curl -I https://panel.example.com/panel/
curl -I https://panel.example.com/sub/
```

Ссылки на подписку и ссылки на узлы больше не должны появляться:

```text
:2096
:40000
:1443
127.0.0.1
```

## Перенести существующий веб-сайт Caddy

### Записи перед миграцией

```bash
find /etc/caddy -maxdepth 3 -type f -print
grep -R "reverse_proxy" /etc/caddy 2>/dev/null
grep -R "tls " /etc/caddy 2>/dev/null
```

Зарегистрируйте каждый сайт:

| домен | серверный протокол | Внутренний адрес | внутренний порт | Примечания |
|---|---|---|---|---|
| `site.example.com` | HTTP | `127.0.0.1` | `8080` | веб-сайт |
| `sub.example.com` | HTTP | `127.0.0.1` | `3000` | Инструмент подписки |

### Включить пост-запись 443

Первая настройка или повторное применение повторного использования порта 443 может изолировать старую конфигурацию Caddy и старую конфигурацию обратный прокси Nginx HTTPS, управляемую сценариями, чтобы предотвратить продолжение захвата старой конфигурацией публичный порт `443`. После его включения не записывайте старые правила вытеснения `443` вручную, а составляйте записи одну за другой:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]
```

При добавлении заполняйте только локальный бэкенд:

| Ввод | Пример |
|---|---|
| Веб-сайт/обратное домен | `site.example.com` |
| Серверный адрес прослушивания | `127.0.0.1` |
| внутренний порт | `8080` |

Проверьте:

```bash
curl -I http://127.0.0.1:8080/
curl -I https://site.example.com/
openssl s_client -connect серверIP:443 -servername site.example.com </dev/null
```

## Перенос существующего веб-сайта Nginx/Apache.

В режиме повторного использования порта 443 публичный порт `443` должна обслуживать только одна служба — служба текущего режима входа. Старые Nginx, Apache, панель и Xray не должны напрямую слушать этот порт. Чтобы сохранить Nginx для обратного прокси сайта, выберите локальный веб-прокси Nginx в `[19] -> [8]`, а не оставляйте старый публичный сервер на порту `443`.

Рекомендуемые практики:

1. Измените старый сервис веб-сайта на собственный бэкэнд HTTP, например `127.0.0.1:8080`.
2. Используйте «Управление именем веб-домена/обратным прокси-сервером» повторного использования порта 443, чтобы выполнить обратный прокси-сервер доменного имени на бэкенд.
3. Подтвердите домен Интернета HTTPS.
4. Проверьте работу новой схемы, затем ужесточите правила брандмауэра и закройте старые публичные порты.

Проверьте старые сервисы:

```bash
ss -lntp | grep -E ':80|:443|:8080|:8081'
grep -R "listen" /etc/nginx /etc/apache2 /etc/httpd 2>/dev/null
```

Если старый сервис должен продолжать использовать Nginx/Apache, по крайней мере, не позволяйте ему захватить `0.0.0.0:443`.

## Перенос инструмента подписки Docker

Цель состоит в том, чтобы бэкенд контейнера была привязана только к локальному компьютеру или интрасети, а Интернет использовал только обратный прокси-сервер Caddy/Nginx или повторное использование порта 443. После включения повторного использования порта 443 Caddy/Nginx становится дополнительным механизмом обратного локального веб-прокси и больше не подключается напрямую к Интернету `443`.

Давайте сначала посмотрим на порт контейнера:

```bash
docker ps --format 'table {{.Names}}\t{{.Ports}}'
ss -lntp | grep -E ':3000|:3001|:3002'
```

Если бэкенд подвержена воздействию `0.0.0.0`, рассмотрите:

```text
Главное меню [11 Docker Управление безопасностью] -> [3 включить Docker Локальное противодействие проникновению]
```

Эта операция повлияет на поведение сети Docker. Перед выполнением убедитесь, что контейнер не использует порт прямого подключения к Интернету.

Если повторное использование порта 443 временно не активирован, введите:

```text
Главное меню [4 обратный прокси]
```

Выберите `[1 добавить Caddy обратный прокси]` или `[2 добавить Nginx HTTPS обратный прокси]`, чтобы выполнить обратный проксирование подписанного доменного имени на локальный внутренний порт. Обратный прокси-сервер Nginx HTTPS будет применяться или повторно использовать сертификат `/etc/caddy/certs/${domain}.crt|key`, а Nginx будет напрямую связан с Интернетом 80/443; этот метод не может одновременно делить вход с 443 и захватить интернет `443`.

Если повторное использование порта 443 включен или готов к включению, добавьте внешнее домен через повторное использование порта 443:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]
```

И измените адрес внешнего доступа на:

```text
https://sub.example.com/
```

Не пишите:

```text
http://127.0.0.1:3000/
http://серверIP:3000/
https://sub.example.com:3000/
```

## Контрольный список проверки после миграции

| Проверить элементы | команда или запись | Ожидание |
|---|---|---|
| Прослушивание портов | `ss -lntp` | публичный порт `443` обслуживает только текущий вход. |
| Конфигурация Nginx | `nginx -t` | Пройти |
| Конфигурация Caddy | `caddy validate --config /etc/caddy/Caddyfile` | Проходит при использовании Caddy в качестве механизма обратного веб-прокси. |
| Панель управления | `curl -I http://127.0.0.1:40000/panel/` | 200/302/401 допустимы, но в соединении нельзя отказать. |
| бэкенд подписки | `curl -I http://127.0.0.1:2096/sub/` | возможность подключения |
| Панель публичной сети | `curl -I https://panel.example.com/panel/` | HTTPS нормальный |
| Публичная сеть веб-сайта | `curl -I https://site.example.com/` | HTTPS нормальный |
| 443 проверка состояния | `Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]` | Нет критического сбоя |
| Обзор услуг | `Главное меню [15 Обзор состояния служб]` | Никаких исключений, неудачная служба |

Резервное копирование сразу после успеха:

```text
Главное меню [16 Резервное копирование и откат конфигурации] -> [1 Создать полную резервную копию конфигурации]
```

## Сценарий отката

| вопрос | Приоритизация обработки |
|---|---|
| Просто добавить новый сайт не удалось | Удалите только что добавленное домен или используйте скрипт для автоматического отката. |
| Конфигурация Caddy не удалась. | Проверьте Caddy, изолируйте новую конфигурацию сайта и затем перезагрузите компьютер. |
| Nginx stream не удалось | Откат 443 конфигурации с повторным использованием порта 443 |
| Панель невозможно открыть | Очистите 3x-ui SSL, проверьте локальный порт и путь. |
| В целом хаотичный сервис | Восстановление из полной резервной копии по сценарию или облачного снимка |

443 Запись отката общей записи:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [12 CF DNS / Caddy Обслуживание сертификатов] -> [6 откат 443 Конфигурация с повторным использованием порта 443]
```

Запись полного отката скрипта:

```text
Главное меню [16 Резервное копирование и откат конфигурации] -> [3 Восстановить из резервной копии]
```

Информацию о потере соединения или сложных неисправностях см. в разделе [recovery-runbook.md](recovery-runbook.md).

## Распространенные ошибки миграции

| Ошибка | Последствия | Правильный подход |
|---|---|---|
| Настройте его напрямую в первый раз, не проводя инвентаризацию старого занятости `443`. | Конфликт портов Nginx/Caddy | Сначала `ss -lntp`, записываем старый сервис |
| Повторно запустите первую конфигурацию при добавлении нового веб-сайта. | Конфигурации неоднократно переписываются, что усложняет устранение неполадок. | Последующие новые дополнения будут доступны только на `[8 менеджмент Web домены / обратный прокси]`. |
| Зарезервировано 3x-ui Поставляется с HTTPS | Цикл перенаправления или 502 | Очистите путь к сертификату и позвольте механизму веб-обратный прокси взять на себя управление HTTPS. |
