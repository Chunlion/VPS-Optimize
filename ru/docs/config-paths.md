# Файлы конфигурации и каталоги данных

Этот документ используется для быстрого поиска файлов во время устранения неполадок, резервного копирования и миграции. Путь может незначительно отличаться в зависимости от системы, стороннего установщика и пользовательской конфигурации. Фактический путь основан на текущей машине.

Путь к меню в этой статье записан в формате «главное меню [копия номера меню] -> [копия меню подномера]».

## Сначала взгляните на пункт меню

## VPS-Optimize сам

| путь | Описание |
|---|---|
| `/usr/local/bin/cy` | Быстрый ввод основного скрипта |
| `vps.sh` текущего каталога | Загрузите файл сценария времени выполнения вручную. |
| `/etc/vps-optimize` | Конфигурация VPS-Optimize, индекс резервного копирования и каталог карантина |
| `/etc/vps-optimize/language.conf` | Настройка языка интерфейса; поддерживает `LANGUAGE=zh`, `LANGUAGE=en`, `LANGUAGE=ru` |
| `/etc/vps-optimize/backups` | Полное резервное копирование и 443 каталога резервного копирования с повторным использованием порта 443 |
| `/etc/vps-optimize/quarantine` | Изолировать каталог. Скрипт пытается переместить сюда старые конфигурации, а не удалять их напрямую. |

Часто используемые проверки:

```bash
ls -lah /etc/vps-optimize 2>/dev/null
find /etc/vps-optimize/backups -maxdepth 2 -type d 2>/dev/null
find /etc/vps-optimize/quarantine -maxdepth 2 -type d 2>/dev/null
```

## повторное использование порта 443

| путь | Описание |
|---|---|
| `/etc/vps-optimize/sni-stack.env` | Основные параметры повторного использования порта 443; `ENTRY_MODE` хранит режим входа, а `STRICT_SNI_GATE` — состояние строгого контроля SNI |
| `/etc/vps-optimize/443-engine.conf` | Текущее состояние механизма общих записей 443, по умолчанию `nginx-stream` |
| `/etc/vps-optimize/vpso-mux.yaml` | Конфигурация маршрутизацияа `tcp-peek` / `vpso-mux` |
| `/etc/vps-optimize/sni-stack.last-backup` | Самая последняя запись пути резервного копирования повторного использования порта 443. |
| `/etc/vps-optimize/backups/sni-stack_*` | 443 Каталог автоматического резервного копирования с повторным использованием порта 443 |
| `/etc/nginx/stream.d/vps_sni_*.conf` | Nginx stream SNI конфигурация маршрутизацияа |
| `/etc/caddy/conf.d/<domain>.caddy` | Конфигурация обратного прокси-сервера Caddy с одним доменным именем |
| `/etc/caddy/certs/<domain>.crt` | Цепочка сертификатов, используемая Caddy |
| `/etc/caddy/certs/<domain>.key` | Закрытый ключ, используемый Caddy |
| `/root/cert/<domain>.crt` | символическая ссылка на сертификат для просмотра пользователем |
| `/root/cert/<domain>.key` | символическая ссылка на закрытый ключ для просмотра пользователем |
| `/root/cert/caddy_cf_manifest.txt` | Список управляемых доменных имен и путей сертификации |
| `/root/cert/acme_last_error.log` | Самый последний журнал ошибок acme, проверьте еще раз, существует ли он. |
| `/etc/systemd/system/vpso-mux.service` | `vpso-mux` маршрутизация systemd Сервисное обслуживание |
| `/usr/local/bin/vpso-mux` | маршрутизация vpso-mux в режиме TCP Peek + Splice |

Проверьте текущие 443 параметра:

```bash
grep -E '^(ENTRY_MODE|STRICT_SNI_GATE|PANEL_DOMAIN|PANEL_WEB_PATH|REALITY_SNI|NGINX_LISTEN_ADDR|NGINX_LISTEN_PORT|CADDY_LISTEN_PORT|XRAY_LISTEN_PORT|SUB_URI_PATH|CLASH_URI_PATH)=' /etc/vps-optimize/sni-stack.env 2>/dev/null
```

Проверьте Nginx/Caddy:

`8443`, `1443`, `40000` и `2096` в команде являются типичными примерами портов; фактическая конфигурация зависит от текущей привязки службы и сохраненной конфигурации сценария.

```bash
nginx -t
caddy validate --config /etc/caddy/Caddyfile
ss -lntp | grep -E ':443|:8443|:1443|:40000|:2096'
```

Сопутствующие входы:

```text
Главное меню [16 Резервное копирование и откат конфигурации] -> [5 Просмотреть или изменить применённую конфигурацию]
Главное меню [19 Управление повторным использованием порта 443] -> [13 443 Проверка соединения]
Главное меню [19 Управление повторным использованием порта 443] -> [6 Повторно применить текущий режим входа]
Главное меню [19 Управление повторным использованием порта 443] -> [12 CF DNS / Caddy Обслуживание сертификатов]
```

## Caddy

| путь | Описание |
|---|---|
| `/etc/caddy/Caddyfile` | Основная конфигурация Caddy |
| `/etc/caddy/conf.d` | VPS-Optimize — рекомендуемый каталог модульной конфигурации сайта. |
| `/etc/caddy/conf.d/*.caddy` | Конфигурация обратный прокси для каждого доменного имени |
| `/etc/caddy/certs` | Каталог сертификатов DNS, записанный после выдачи |
| `/etc/caddy/Caddyfile.bak_*` | Резервное копирование перед сценарием или ручным изменением |
| `/etc/caddy/conf.d_quarantine_*` | Старый каталог изоляции конфигурации, имя может иметь метку времени. |

Часто используемые команды:

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl status caddy --no-pager
journalctl -u caddy -n 100 --no-pager
find /etc/caddy -maxdepth 3 -type f
```

Если это просто обратный прокси, запись будет такой:

```text
Главное меню [4 обратный прокси] -> [1 добавить Caddy обратный прокси]
Главное меню [4 обратный прокси] -> [2 добавить Nginx HTTPS обратный прокси]
Главное меню [4 обратный прокси] -> [6 Просмотреть или изменить применённые файлы конфигурации]
```

Если включен повторное использование порта 443, новый вход на веб-сайт:

```text
Главное меню [19 Управление повторным использованием порта 443] -> [8 менеджмент Web домены / обратный прокси]
```

## Nginx

| путь | Описание |
|---|---|
| `/etc/nginx/nginx.conf` | Основная конфигурация Nginx |
| `/etc/nginx/stream.d` | 443 Каталог конфигурации потока с повторным использованием порта 443 |

| `/etc/nginx/conf.d/00-vps-default-drop.conf` | Конфигурация отброшенного сайта по умолчанию используется для уменьшения воздействия на сайт по умолчанию, если он присутствует. |
| `/etc/nginx/conf.d/00-vps-proxy-map.conf` | Nginx HTTPS Обратное сопоставление переменных соединения WebSocket |
| `/etc/nginx/conf.d/vps_proxy_*.conf` | Nginx HTTPS Конфигурация сайта обратный прокси |
| `/etc/nginx/conf.d` | Традиционный каталог конфигурации Nginx HTTP |
| `/etc/nginx/sites-enabled` | Общий каталог включения сайта Debian/Ubuntu |
| `/etc/nginx/sites-available` | Доступные каталоги общего сайта Debian/Ubuntu |

Часто используемые команды:

```bash
nginx -t
systemctl status nginx --no-pager
journalctl -u nginx -n 100 --no-pager
grep -R "listen" /etc/nginx 2>/dev/null
```

443 В режиме повторного использования порта 443 сеть общего пользования `443` должна контролироваться только службой повторного использования порта 443, соответствующей текущему `ENTRY_MODE`: `nginx-stream` соответствует `nginx`, а `xray-fallback` соответствует Xray/3x-ui/x-ui. управляемые Xray, `tcp-peek` соответствуют `tcppeek`/`vpso-mux`. Если `/etc/vps-optimize/sni-stack.env` не имеет `ENTRY_MODE`, скрипт считается совместимым с `nginx-stream`.
