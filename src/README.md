# Source Module Boundaries

`dist/vps.sh` is the release artifact generated by `scripts/build.sh`. Runtime users should install `dist/vps.sh`; `src/*.sh` is for development and review.

Build order is intentional. Foundational helpers are loaded first, then focused feature modules, then the bootstrap:

1. `common.sh`
   Constants, OS detection, package helpers, shortcut registration, remote download/execution, and shared installer helpers.
2. `ui.sh`
   Display helpers and high-risk confirmation prompts.
3. `input.sh`
   Input trimming, secret input, defaults, and CSV/pipe splitting.
4. `validate.sh`
   Domain, port, IP/CIDR, path, DNS, Caddy/Nginx formatting validation and normalization.
5. `rollback.sh`
   Quarantine, restore, and SNI/DNS rollback helpers.
6. `backup.sh`
   Backup center and reusable backup copy/restore orchestration.
7. `runtime.sh`
   Root/runtime guard.
8. Feature modules
   `system_core.sh`, `caddy_certificates.sh`, `caddy_proxy.sh`, `environment.sh`, `caddy_legacy.sh`,
   `sni_stack_*.sh`, `tcp_peek_engine.sh`, `xray_sni_routes.sh`, `caddy_maintenance.sh`,
   `ssh_security.sh`, `docker_manage.sh`, `kernel_tuning.sh`, `diagnostics_*.sh`,
   `panel_installers.sh`, `subscription_tools.sh`, `panel_rescue.sh`, `server_maintenance.sh`,
   `updater.sh`, `preflight.sh`, `health_dashboard.sh`, `dns_optimize.sh`,
   `traffic_guard.sh`, and `network_interface.sh`.
9. `menus.sh`
   Help text plus top-level and second-level menu wiring.
10. `main.sh`
   Bootstrap only; calls `main_menu`.

Rules for new code:

- Put reusable shell primitives in `common.sh`, `ui.sh`, `input.sh`, `validate.sh`, `rollback.sh`, or `backup.sh`.
- Put feature-specific flows in the nearest focused feature module.
- Keep `main.sh` as a tiny bootstrap so the generated release script still starts from the same menu.
- Do not make the release script source `src/*.sh` at runtime; regenerate `dist/vps.sh` with `scripts/build.sh`.
- Keep menu numbers stable for backward compatibility; prefer adding aliases or moving display groups over renumbering existing entries.

Minimum verification after editing any `src/*.sh` module:

1. `bash -n src/*.sh`
2. `bash scripts/build.sh`
3. `bash -n dist/vps.sh`
4. `bash tests/smoke.sh`

`tests/smoke.sh` is the reusable release gate: it rebuilds `dist/vps.sh`, checks shell syntax, runs `GOTOOLCHAIN=local go test ./...` for `vpso-mux`, and asserts key 443/TCP Peek release menu wiring.
