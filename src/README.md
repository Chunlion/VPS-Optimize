# Source Module Boundaries

`dist/vps.sh` is the release artifact generated by `scripts/build.sh`. Runtime users should install `dist/vps.sh`; `src/*.sh` is for development and review.

Build order is intentional:

1. `common.sh`
   Constants, OS detection, package helpers, shortcut registration, remote download/execution, and shared installer helpers.
2. `ui.sh`
   Display helpers and high-risk confirmation prompts.
3. `input.sh`
   Input trimming, secret input, defaults, and CSV/pipe splitting.
4. `validate.sh`
   Domain, port, IP/CIDR, path, DNS, Caddy/Nginx formatting validation and normalization.
5. `rollback.sh`
   Quarantine, restore, and SNI/DNS rollback helpers.
6. `backup.sh`
   Backup center and reusable backup copy/restore orchestration.
7. `main.sh`
   Feature implementation, service workflows, and menu wiring.

Rules for new code:

- Put reusable shell primitives in `common.sh`, `ui.sh`, `input.sh`, `validate.sh`, `rollback.sh`, or `backup.sh`.
- Put feature-specific flows in `main.sh` until a feature family becomes stable enough to split into its own module.
- Do not make the release script source `src/*.sh` at runtime; regenerate `dist/vps.sh` with `scripts/build.sh`.
- Keep menu numbers stable for backward compatibility; prefer adding aliases or moving display groups over renumbering existing entries.
